## 1. 목적 (Why)

- 개인이 하루/주/월 단위 일정을 **등록·분류·완료 관리**하고, 일정 시각 전에 **알림**을 받아 할 일을 놓치지 않도록 돕는다.
- "오늘 해야 할 일"을 한 화면(대시보드)에서 완료/미완료로 파악하게 한다.
- 기기의 **기본 캘린더**와 연동하여 기존 일정 흐름을 깨지 않는다.

### 성공 판단 기준 (제품 관점, 정성)

- 사용자가 일정 등록부터 알림 수신, 완료 체크까지 앱을 벗어나지 않고 수행할 수 있다.
- 알림이 설정한 시각/사전 간격에 실제로 도달한다.
- 앱을 재실행해도 등록한 일정과 설정이 그대로 유지된다.

## 2. 사용자 식별 (Who)

| 사용자 | 설명 | 주 사용 시나리오 |
| --- | --- | --- |
| 개인 사용자 (기본) | 앱을 설치한 단말의 소유자. 로그인 없이도 사용 가능 | 일정 등록, 알림 수신, 완료 체크, 검색 |
| 계정 연동 사용자 | 외부 계정(예: Google 등)을 연동한 개인 사용자 | 여러 기기 간 일정 동기화, 기본 캘린더 연동 |
| 스마트워치 사용자 | "오늘뭐해" 모바일 앱과 페어링된 워치 착용자. 이번 릴리스 대상은 **애플워치(watchOS)** (F-19) | 알림 확인, 금일 일정 조회, 완료/미완료 토글 |

- 다중 사용자(팀/공유 일정), 관리자, 게스트 개념은 이번 범위에 **없음(확정)**.
- 스마트워치 사용자의 이번 릴리스 대상 플랫폼은 **애플워치(watchOS)** 로 한정한다(F-19). Android Wear OS(안드로이드 워치)는 후속 범위다(OI-11).

## 3. 범위 (Scope)

### 3.1 이번 릴리스 포함 (확정)

1. 일정 관리 (CRUD, 완료 체크, 유형, 우선순위)
2. 알림 (사전 알림 + 정시 알림)
3. 대시보드 (금일/선택 날짜 완료·미완료 집계 + 목록에서 직접 완료 토글·스와이프 삭제 — 상호작용형, F-10) + 날짜 탐색(어제/내일/오늘 복귀, 시각적으로 작게, F-20) + 진행률 한 줄("M / N 완료" 텍스트 + progress bar 1개, 미래 날짜는 총 개수만, F-21) + 접이식 날짜별 검색(검색 아이콘 토글, F-22)
4. 일정 검색
5. 계정 연동
6. 스타일(테마) 지정
7. 기본 캘린더 연동
8. 앱 아이덴티티 UI (로고·태그라인·탭 아이콘 — F-16)
9. 브랜드 로딩 인디케이터 (로고 오리 캐릭터 애니메이션 — F-17)
10. 유형(카테고리) 관리 — 전용 화면에서 추가·이름변경·삭제 (F-06)
11. 앱 설정 — 전역 알림 사용 토글, 새 일정 기본값(중요도·유형) 지정 (F-18)
12. 애플워치(watchOS) 워치 앱 — 오늘 일정 읽기 조회 + 완료/미완료 토글 중심의 축소 클라이언트 (F-19, NFR-10 승격)

### 3.2 이번 릴리스 제외 (확정)

- 팀/공유 일정, 일정 위임, 초대
- 반복 일정의 복잡한 예외 규칙(RFC 5545 전체) — 아래 5.1의 제한된 반복만 포함
- 위치 기반 알림, 음성 입력
- 웹/데스크톱 클라이언트
- **Android Wear OS 워치 앱** — F-19는 애플워치(watchOS)만 포함한다. Wear OS 및 Wear Data Layer 동기화는 후속(OI-11). Android Wear Data Layer는 후속 설계의 참고 사항일 뿐 이번 릴리스에서 구현하지 않는다.
- 워치에서의 일정 생성·편집·삭제·스누즈·유형 관리·검색·설정/테마/캘린더 연동 변경 — 폰 전용(F-19 비범위, P-43)
- 워치 앱이 독립적으로 로컬 알림을 예약하는 것 — 알림 예약 주체는 폰(P-41)

### 3.3 가정 (Assumption — Architect/이해관계자 확인 필요)

- **A-1**: "계정 연동"은 (a) 외부 OAuth 로그인 + 자체 동기화 서버 도입, (b) 단말 OS 계정(Google/Apple)에 붙어 캘린더 API만 사용, (c) 로그인만 하고 동기화는 캘린더 연동에 위임 중 하나다. 본 기획은 **(c)를 기본 가정**으로 하며 최종 결정은 이해관계자(정책 게이트 D-01)에 위임한다.
- **A-2**: 스마트워치 앱은 모바일 앱의 **보조 클라이언트**이며 독립 저장소를 갖지 않는다(모바일과 동기화된 데이터를 표시).
- **A-3**: 오프라인이 기본 동작 환경이다. 네트워크는 계정 연동/캘린더 동기화 시에만 필요하다.
- **A-4**: 개인정보(일정 제목/메모)는 단말 로컬(SQLite)에 저장된다. 서버 저장 여부는 D-01에 종속.
- **A-5**: 폰↔워치 동기화 채널은 iOS(WatchConnectivity)를 이번 범위의 주 대상으로 한다. 구체 전송 메커니즘(application context / 메시지 / 파일 트랜스퍼 등) 선택과 코어 로직의 워치 번들링 방식은 Architect 설계 사항이다. Android Wear Data Layer는 후속 참고용이다.

## 4. 기능 요구사항 (What / Action / Result / Exception)

표기: **확정** = 원본 요구사항에서 직접 도출 / **가정** = Planner가 보완(검증 필요)

### F-01 일정 등록 (확정)

- Who: 개인 사용자
- When: 앱 실행 중 언제든
- What: 새 일정을 생성한다
- Action: 제목, 시작 일시, (선택) 종료 일시, 유형, 우선순위, (선택) 메모, 알림 설정을 입력하고 저장한다
  - 중요도·유형 필드의 초기 선택값은 설정된 "새 일정 기본값"(F-18, P-33)을 따른다. 미설정 시 각각 "보통"·"기타".
- Result: 일정이 저장되고 목록/대시보드/캘린더 뷰에 즉시 반영된다. 알림 설정이 있고 전역 "알림 사용"이 on(P-32)이면 알림이 예약된다
- Exception:
  - E-01-1 제목이 비어 있음 → 저장 불가, 안내 메시지
  - E-01-2 시작 일시 미선택 → 저장 불가
  - E-01-3 종료 일시가 시작보다 빠름 → 저장 불가
  - E-01-4 과거 시각으로 사전 알림 설정 → 알림은 예약하지 않고 일정만 저장, 경고 표시

### F-02 일정 조회 (확정)

- Who: 개인 사용자 / 워치 사용자
- What: 등록된 일정을 목록·일간·주간·월간으로 본다
- Action: 날짜 이동, 뷰 전환, 일정 선택 시 상세 표시
- Result: 선택 기간의 일정이 시간순으로 표시된다. 완료 항목은 시각적으로 구분된다
- Exception:
  - E-02-1 해당 기간에 일정 없음 → 빈 상태 안내
  - E-02-2 데이터 로드 실패 → 재시도 안내, 마지막 캐시 표시

### F-03 일정 수정 (확정)

- Action: 기존 일정의 필드를 변경하고 저장 (수정 화면은 저장된 기존 값을 표시하며, "새 일정 기본값" P-33을 적용하지 않는다)
- Result: 변경 내용 저장, 알림 설정이 바뀌면 기존 예약 취소 후 재예약. 단 전역 "알림 사용"이 off(P-32)면 재예약하지 않고 기존 예약은 취소 상태를 유지한다
- Exception: F-01의 검증 규칙 동일 적용. 이미 완료된 일정도 수정 가능(정책 P-05)

### F-04 일정 삭제 (확정)

- Action: 일정을 삭제한다
- Result: 일정 및 연결된 알림 예약이 제거된다. 삭제 확인 절차를 거친다
- Exception:
  - E-04-1 캘린더 연동으로 생성된 일정 삭제 → 정책 P-08에 따름
  - E-04-2 삭제 취소(Undo)는 저장 직후 일정 시간 내 제공(가정)

### F-05 완료 체크 (확정)

- Who: 개인 사용자 / 워치 사용자
- Action: 일정의 체크박스를 토글한다
- Result: 완료/미완료 상태가 즉시 저장되고 대시보드 집계에 반영된다. 완료 시각을 기록한다
- Exception:
  - E-05-1 미래 일정도 완료 체크 가능(정책 P-06)
  - E-05-2 저장 실패 → 상태 롤백, 재시도 안내

### F-06 유형(카테고리) 지정 및 관리 (확정)

- Who: 개인 사용자
- When: 일정 작성/수정 시(지정) / 설정의 "유형 관리" 화면 진입 시(관리)
- What: 일정을 유형으로 분류하고, 사용자 정의 유형을 직접 관리한다 (예: 취미, 공부, 업무)
- Action:
  - **지정**: 일정 작성/수정 시 유형 목록에서 하나를 선택한다.
  - **관리(전용 화면 — 확정)**: 설정 → "유형 관리" 화면에서 유형 목록을 조회하고,
    - 새 유형을 **추가**한다(이름 입력).
    - 기존 유형의 **이름을 변경(rename)** 한다.
    - 기존 유형을 **삭제**한다.
  - 유형 관리 화면 진입점은 설정 화면에 둔다(F-18 / F-13 설정 화면 내).
- Result:
  - 지정한 유형이 목록·대시보드·캘린더·검색에서 해당 일정의 유형 라벨로 표시된다.
  - 유형별 색상/아이콘으로 구분 표시하고, 유형별 필터·검색이 가능하다.
  - 유형 추가/이름변경/삭제 결과가 유형 선택 UI와 기존 일정 표시에 즉시 반영된다.
  - 일정은 유형을 **ID로 참조**하므로, 유형 이름을 바꿔도 그 유형을 쓰던 모든 일정의 표시 라벨이 새 이름으로 즉시 갱신된다(연결 유지).
- Exception:
  - E-06-1 유형 미선택 → 기본 유형("기타")으로 저장 (단, 새 일정 기본값이 설정되어 있으면 P-33 적용)
  - E-06-2 사용 중인 유형 삭제 → 해당 유형을 쓰던 일정은 기본 유형("기타")으로 이동, 삭제 확인 절차를 거친다
  - E-06-3 유형 추가/이름변경 시 이름이 비어 있거나 공백만 있음 → 저장 불가, 안내 메시지
  - E-06-4 유형 추가/이름변경 시 기존 유형과 이름이 중복(앞뒤 공백 제거 후 대소문자 무시 비교) → 저장 불가, 안내 메시지
  - E-06-5 기본 유형("기타")에 대한 삭제 또는 이름변경 시도 → 허용하지 않음(해당 조작 UI 비활성 또는 시도 시 거부·안내). P-34
  - E-06-6 유형 삭제 중 저장 실패 → 삭제를 취소하고 목록을 원상 복구, 재시도 안내

### F-07 우선순위 지정 (확정)

- What: 일정에 우선순위를 부여한다
- Action: 높음/보통/낮음 3단계 중 선택(가정: 단계 수)
- Result: 목록에서 우선순위 표식 표시, 우선순위로 정렬·필터 가능
- Exception: E-07-1 미선택 → "보통"으로 저장

### F-08 사전 알림 (확정)

- Who: 개인 사용자
- When: 일정 시작 시각 기준 사전 오프셋(예: 1일 전, N분 전) 도달 시
- What: 일정 시작 전에 미리 알림을 보낸다
- Action: 일정별로 사전 알림 오프셋을 0개 이상 설정 (프리셋: 5/10/30분, 1시간, 1일 + 사용자 지정)
- Result: 각 오프셋 시각에 로컬 알림(제목/시각/유형 표시)이 발송된다. 워치에도 전달된다
- Exception:
  - E-08-1 알림 권한 거부 → 앱 내 안내, 설정 이동 유도, 일정은 정상 저장
  - E-08-2 오프셋 시각이 이미 과거 → 해당 오프셋은 건너뜀
  - E-08-3 기기 재부팅/앱 강제종료 후 → 예약이 복원되어야 함(정책 P-09)
  - E-08-4 방해 금지 시간대 → OS 정책에 따름, 앱은 별도 우회하지 않음
  - E-08-5 전역 "알림 사용"이 off(F-18, P-32) → 사전 알림을 예약하지 않는다. 일정의 알림 설정값 자체는 보존한다

### F-09 정시 알림 (확정)

- When: 일정 시작 시각 도달 시
- Result: "지금 시작" 알림 발송
- Exception: F-08의 예외 규칙을 동일 적용

### F-10 대시보드 (상호작용형 — 확정, v1.3 재정의 / v1.6 날짜 탐색(작게)·진행률 한 줄·접이식 검색으로 재정의)

- Who: 개인 사용자 / 워치 사용자
- What: 기준 날짜(기본값 오늘, F-20으로 ±1일 이동 가능)의 일정 완료/미완료 현황을 요약하고, 같은 화면에서 그 날짜의 일정을 직접 처리한다
- 화면 구조 (한 화면 공존 — 확정, 위→아래 순 / v1.6 재확정 방향): **상단 브랜드 → 날짜 네비(작게) → 진행률 한 줄 → 접이식 검색 → 요약 상세 → 오늘 일정 리스트 → FAB**
  - **상단 브랜드 영역**: 로고(logo.png)와 태그라인(tagline.png)을 표시한다. (F-16 / AC-25 회귀 방지 — v1.3·v1.5·v1.6에서 유지 요건으로 재확인)
  - **날짜 네비게이션 영역** (F-20, v1.5 신규 / v1.6 "작게" 요건 추가): 기준 날짜 표시 + 좌/우 화살표 + (오늘이 아닐 때) "오늘로" 복귀 컨트롤. **시각적으로 작게(컴팩트)** 배치하여 그 아래 진행률 한 줄·리스트가 화면을 차지하게 한다(구체 크기는 설계).
  - **진행률 한 줄 영역** (F-21, v1.6 재정의 — 기존 "개수 카드 영역"): 기준 날짜의 **"M / N 완료" 형식 텍스트 + 얇은 progress bar 1개**를 한 줄로 표시한다. 기존 "요약 영역"의 카운트 표현을 한 줄 요약으로 구체화한 것이며 별도 집계 규칙을 만들지 않는다(P-47). 미래 기준 날짜에서는 progress bar·완료율을 숨기고 총 일정 수만 표시한다(P-52).
  - **접이식 검색 영역** (F-22, v1.6 재정의 — 기존 "인라인 검색 영역"): 진행률 한 줄과 리스트 사이에 **검색 아이콘**을 두고, 탭하면 펼쳐지는(collapsible) 검색 입력창. 펼친 상태에서 기준 날짜의 일정 목록 안에서만 검색한다. 펼침/접힘은 대시보드 로컬 상태(P-53).
  - **요약 상세 영역**: 완료율(%), 유형별 분포, 다음 예정 일정을 표시한다. (v1.3·v1.5·v1.6에서 유지 요건으로 재확인 — 진행률 한 줄이 이 영역을 대체하지 않는다)
  - **오늘 일정 리스트 영역**: 기준 날짜의 일정을 시간순 목록으로 표시하고, 아래 상호작용을 지원한다. 접이식 검색이 펼쳐져 검색어가 있으면 그 결과로 필터되어 표시된다(F-22).
  - **일정 추가 진입점(FAB)**: 화면에 상시 표시되는 플로팅 추가 버튼. (AC-15 참조)
- v1.6 관계: 대시보드의 "기준 날짜" 상태는 F-20이 관리한다. 기준 날짜가 오늘이 아니면 진행률 한 줄·요약·목록이 모두 그 날짜 기준으로 표시된다(미래 날짜의 진행률 한 줄 표시는 P-52). 완료 토글·스와이프 삭제·FAB 규칙은 날짜와 무관하게 동일하다(과거/미래 날짜에서 FAB로 추가 시 작성 화면 기본 일시 프리필은 OI-19).
- Action:
  - 앱 첫 화면에서 요약과 목록을 확인한다.
  - 목록 항목의 완료 체크를 **탭하여 완료/미완료를 직접 토글**한다(F-05 재사용).
  - 목록 항목을 **스와이프하여 삭제**한다(F-04 재사용, 공통 스와이프 컴포넌트).
  - 목록 항목 본문을 탭하면 해당 일정 상세로 이동한다.
  - FAB를 탭하면 일정 작성 화면으로 이동한다.
- Result:
  - 완료 토글 시 완료 상태가 즉시 저장되고 요약(완료 수·미완료 수·완료율·유형별 분포)이 실시간 갱신된다.
  - 스와이프 삭제 시 삭제 확인 후(F-04) 일정과 그 알림 예약이 제거되고 목록·요약에서 사라진다.
  - 요약 영역과 목록 영역은 항상 한 화면에 함께 표시된다(요약만 있는 화면 또는 목록만 있는 화면으로 축소하지 않는다).
- Exception:
  - E-10-1 금일 일정 0건 → 요약 영역은 0/0/0%로 표시하고, 목록 영역에 "오늘 일정이 없습니다" 안내와 명시적 "일정 추가" 버튼을 표시한다. FAB도 함께 표시된다. (AC-15)
  - E-10-2 자정 경과 → 기준 날짜가 "그 시점의 오늘"이었으면 새 오늘로 자동 갱신된다. 사용자가 F-20으로 다른 날짜를 보고 있었다면 그 날짜를 유지한다(P-46).
  - E-10-3 인라인 완료 토글 저장 실패 → 체크 상태를 원래대로 롤백하고 재시도 안내(F-05 E-05-2 준용)
  - E-10-4 스와이프 삭제 확인 취소 → 삭제하지 않고 목록을 원상 복구
  - E-10-5 캘린더 연동으로 생성된 일정 스와이프 삭제 → F-04 E-04-1 / P-08에 따른다
  - E-10-6 목록 데이터 로드 실패 → 요약·브랜드 영역은 유지하고 목록 영역에 재시도 안내(F-02 E-02-2 준용)

### F-11 일정 검색 (확정)

- What: 제목/메모/유형으로 일정을 찾는다
- Action: 검색어 입력, (선택) 기간·유형·완료여부·우선순위 필터 적용
- Result: 일치 일정을 관련도/날짜순으로 표시, 결과에서 바로 상세 이동
- Exception:
  - E-11-1 검색어 0건 → 빈 결과 안내
  - E-11-2 검색어 1글자 → 허용하되 결과가 많을 수 있음을 안내(가정: 최소 글자수 정책 P-11)
- 관계 (v1.5 / v1.6): 대시보드("오늘" 탭) 안에서 기준 날짜 목록만 대상으로 하는 **접이식 날짜별 검색**은 F-22로 별도 정의한다(v1.6에서 상시 입력창 → 검색 아이콘 토글 접이식으로 재정의). F-11(전역 검색, 검색 탭)과 F-22는 서로 독립이며 검색어·필터가 전파되지 않는다(P-51).

### F-12 계정 연동 (확정, 세부는 가정)

- Who: 계정 연동을 원하는 개인 사용자
- What: 외부 계정을 연동/해제한다
- Action: 계정 로그인(OAuth) → 권한 동의 → 연동 완료. 설정에서 연동 해제 가능
- Result: 연동 상태 표시. (D-01 결정에 따라) 기기 간 동기화 또는 캘린더 접근이 활성화된다
- Exception:
  - E-12-1 로그인 취소/실패 → 로컬 전용 모드 유지
  - E-12-2 토큰 만료 → 재인증 요청, 만료 동안 로컬 동작 유지
  - E-12-3 연동 해제 → 로컬 데이터는 유지, 서버/캘린더 동기화만 중단(가정)

### F-13 스타일(테마) 지정 (확정)

- What: 앱 외형을 사용자가 바꾼다
- Action: 라이트/다크/시스템 테마 선택, 강조 색상 선택, (가정) 글자 크기 조절
- Result: 설정 즉시 앱 전체에 적용되고 재실행 후에도 유지된다
- Exception: E-13-1 시스템 테마 변경 시 "시스템" 선택이면 자동 반영

### F-14 기본 캘린더 연동 (확정)

- What: 단말의 기본 캘린더(iOS EventKit / Android Calendar Provider)와 일정을 주고받는다
- Action: 캘린더 접근 권한 동의 → 가져올 캘린더 선택 → 양방향/단방향 동기화 범위 설정(가정)
- Result:
  - 외부 캘린더 일정이 앱에 표시된다(읽기)
  - 앱에서 만든 일정을 선택한 캘린더에 반영한다(쓰기, 가정: 옵션)
- Exception:
  - E-14-1 권한 거부 → 캘린더 연동 비활성, 앱 자체 일정은 정상
  - E-14-2 동일 일정 중복(앱↔캘린더) → 중복 판정 규칙 P-08로 병합/표시
  - E-14-3 충돌(양쪽 동시 수정) → "기기 캘린더 우선" 기본, 사용자 선택 옵션(가정)
  - E-14-4 대량 일정 → 동기화는 백그라운드로 처리, 진행 표시

### F-16 앱 아이덴티티 UI (확정 — 에셋 제공에 의한 신규 요구사항)

- Who: 개인 사용자
- When: 앱 진입 시 / 탭 전환 시 / 대시보드 화면 표시 시
- What: 제공된 로고·태그라인·탭 아이콘 에셋을 앱 UI에 표시하여 앱 아이덴티티를 강화한다
- Action (확정):
  - **로고(logo.png)**: 대시보드 화면 상단 헤더 영역에 앱 로고를 표시한다
  - **태그라인(tagline.png)**: 대시보드 화면에서 로고 하단에 태그라인 이미지를 표시한다
  - **탭 아이콘**: 하단 탭 내비게이터의 각 탭에 해당 아이콘 이미지를 적용한다
    - 오늘(대시보드) 탭 → `todo.png`
    - 캘린더 탭 → `goal.png`
    - 검색 탭 → `statistics.png`
    - 설정 탭 → `settings.png`
- Result:
  - 대시보드 진입 시 로고와 태그라인이 즉시 표시된다
  - 탭 바에 텍스트만 있던 탭이 아이콘(+텍스트 라벨)으로 표시된다
  - 활성 탭과 비활성 탭을 색상으로 구분한다(활성: 강조색 / 비활성: 회색조)
- Exception:
  - E-16-1 에셋 파일 로드 실패 → 아이콘 영역을 빈 공간 또는 텍스트 라벨로 대체한다(앱 동작에 영향 없음)
  - E-16-2 다크 테마 설정 시 → 아이콘 색상은 테마에 무관하게 원본 PNG를 사용한다(이번 릴리스). 별도 다크 테마 아이콘 변형은 이번 범위 제외
  - E-16-3 고해상도(Retina/XXHDPI) 기기 → RN Image 컴포넌트의 자동 스케일링에 위임한다. 별도 @2x/@3x 에셋은 이번 범위 제외(확정)

### F-17 브랜드 로딩 인디케이터 — 로고 오리 캐릭터 애니메이션 (확정 — 사용자 신규 요청에 의한 요구사항)

**목적 / 배경**

- 앱 로고에 등장하는 오리 캐릭터를 로딩(대기) 표시에 활용하여 **브랜드 아이덴티티를 강화**한다.
- 데이터 로드·처리 대기 시간을 캐릭터의 움직임으로 채워 **대기 체감(perceived wait)을 개선**하고 이탈을 줄인다.
- OS 표준 스피너 대신 앱 고유의 로딩 표현을 제공한다.
- 사용자 요청 원문: "로고의 오리가 여러 일을하는 svg를 만들어 로딩 표시로 띄워줘".

**기본 정의**

- Who: 모든 사용자(개인 사용자 / 계정 연동 사용자). 스마트워치 사용자는 제외(E-17-6).
- When: 앱이 데이터를 불러오거나 처리 중이어서 사용자가 결과를 기다려야 하는 로딩 상태.
- What: 로고의 오리 캐릭터가 이 앱 도메인의 여러 활동을 정해진 순서로 순환(loop)하며 수행하는 벡터(SVG) 기반 애니메이션을 로딩 인디케이터로 표시한다.
- Action: 사용자는 별도 조작을 하지 않는다. 로딩 상태 진입 시 자동으로 표시되고, 로딩 종료 시 자동으로 제거된다.
- Result:
  - R-17-1 로딩 상태가 표시 지연 임계 시간(P-24) 이상 지속되면 오리 애니메이션이 나타난다.
  - R-17-2 오리는 아래 「순환 활동 목록」의 활동을 정의된 순서로 반복한다.
  - R-17-3 각 활동은 일정 시간(P-25, 가정 2~4초) 노출된 뒤 다음 활동으로 급격한 점프 없이 전환된다.
  - R-17-4 로딩이 끝나면 애니메이션이 사라지고(P-26 최소 표시 시간 준수) 실제 콘텐츠가 표시된다.
  - R-17-5 노출 위치에 따라 풀스크린 중앙 또는 인라인(콘텐츠 영역 대체/오버레이)으로 배치된다(「노출 위치」 참고).

**순환 활동 목록** (확정 4개 + 선택 1개, 표기 순서대로 순환)

| 순번 | 활동 | 오리의 시각적 동작 | 로딩 맥락에서의 의미 |
| --- | --- | --- | --- |
| 1 | 일정 확인 | 오리가 할 일 목록/클립보드를 들고 항목을 훑어본다 | 저장된 일정 데이터를 읽어오는 중 |
| 2 | 달력 넘기기 | 오리가 벽걸이 달력의 장을 넘긴다 | 날짜·기간 범위 데이터를 준비하는 중 |
| 3 | 알림 종 울리기 | 오리가 손종을 흔들고 음파(소리) 표시가 퍼진다 | 알림 예약·동기화를 처리하는 중 |
| 4 | 완료 체크 | 오리가 체크박스에 체크 표시를 그린다 | 처리를 마무리하는 중(로딩 완료 임박 인상) |
| 5 (선택) | 검색하기 | 오리가 돋보기로 항목을 살핀다 | 검색 결과를 취합하는 중 (Search 화면 로딩에서 우선 노출) |

- 활동 수는 최소 3개, 최대 5개로 한다(P-23).
- 모든 활동의 도상은 로고 오리의 형태·색을 유지한다. 새 캐릭터를 만들지 않는다.

**노출 위치**

| # | 화면 / 상태 | 유형 | 비고 |
| --- | --- | --- | --- |
| 1 | 앱 부트스트랩(네이티브 스플래시 종료 후 초기 데이터 로드) | 풀스크린 오버레이(중앙, 대형) | 네이티브 스플래시 이미지 자체 교체는 아님(비범위). 스플래시와의 관계는 D-06 |
| 2 | Dashboard 금일/선택 날짜 요약·집계 로딩 (날짜 탐색 이동 포함, F-20) | 인라인(진행률 한 줄·요약 영역 자리, 소형) | 화면의 나머지 UI(브랜드·날짜 네비 영역)는 유지 |
| 3 | Calendar 월/기간 전환 로딩 | 인라인(캘린더 그리드 영역 오버레이, 소형) | 헤더·이동 컨트롤은 계속 조작 가능 |
| 4 | Search 결과 로딩 | 인라인(결과 리스트 영역, 소형) | 활동 5(검색하기)를 첫 활동으로 노출 |
| 5 | 대량 캘린더 동기화(F-14 E-14-4) 등 백그라운드 장기 작업 | 사용 안 함(기존 진행 표시 우선) 또는 소형 인라인만 허용 | 본 인디케이터로 진행률 표시를 대체하지 않는다 |

- 인라인 인디케이터는 화면 폭의 40% 이하, 풀스크린 인디케이터는 60% 이하로 크기를 제한한다(P-27, 구체 수치는 설계).

**Exception**

- E-17-1 OS "동작 줄이기(Reduce Motion)" 활성 → 애니메이션을 재생하지 않고 「정적 폴백」을 표시한다.
- E-17-2 SVG/애니메이션 렌더 실패 → 정적 폴백 이미지로 대체한다. 정적 폴백마저 실패하면 OS 표준 로딩 인디케이터(스피너)를 표시한다. 어떤 경우에도 앱은 크래시하지 않는다.
- E-17-3 로딩이 표시 지연 임계 시간(P-24) 이내에 종료 → 인디케이터를 표시하지 않는다(깜빡임 방지).
- E-17-4 인디케이터 표시 후 로딩이 타임아웃 임계(P-28)를 초과 → 애니메이션은 유지하되 "계속 불러오는 중"류의 보조 문구와 재시도/취소 안내를 함께 노출한다(문구·시간은 설계).
- E-17-5 저사양 기기 또는 배터리 절약 모드에서 프레임 저하가 감지되면 → 정적 폴백으로 자동 전환한다(판정 기준은 설계, P-29).
- E-17-6 스마트워치 클라이언트 → 본 인디케이터를 사용하지 않고 워치 표준 로딩 표시를 사용한다.
- E-17-7 로딩이 에러로 종료 → 인디케이터를 즉시 제거하고 해당 화면의 에러/재시도 UI로 전환한다(F-02 E-02-2 등 기존 규칙에 따름).
- E-17-8 동일 화면에서 로딩이 중첩 발생 → 인디케이터는 1개만 표시한다(중복 렌더 금지).

**정적 폴백 (요구)**

- 오리 캐릭터의 정지 포즈 1컷(대표 활동: "일정 확인")과 하단 "불러오는 중…" 텍스트로 구성한다.
- 폴백 이미지도 로고 오리와 동일한 아이덴티티(형태·색)를 유지한다.
- 폴백 이미지 리소스도 로드 실패 시 최종적으로 OS 표준 인디케이터로 대체한다.
- 정적 폴백은 E-17-1 / E-17-2 / E-17-5 및 애니메이션 미지원 환경에서 사용한다.

**F-17 비범위 (Out of scope)**

- 로고 캐릭터(오리) 자체의 리디자인 — 기존 형태를 유지한다.
- 앱 런처 아이콘(iOS AppIcon / Android mipmap) 변경.
- 기존 DashboardScreen 로고 표시 회귀(T-01) 수정 — 별도 트랙에서 처리한다.
- 로딩 외 상태(빈 상태·에러·성공)용 캐릭터 애니메이션 — 후속(OI-6).
- 로딩 애니메이션에 사운드·햅틱 동반 — 후속.
- 스마트워치용 로딩 애니메이션 — 이번 범위 제외(E-17-6, OI-7).
- 사용자가 로딩 애니메이션 스타일을 커스터마이즈하는 설정 — 후속.
- 기술 선택(예: react-native-svg 등 애니메이션 구현 수단) — Architect 설계 범위.

### F-18 앱 설정 — 전역 알림 사용 토글 / 새 일정 기본값 (확정 — v1.3 재설계분 정식화)

- Who: 개인 사용자
- When: 설정 화면 진입 시 언제든
- What: 앱 전역의 알림 사용 여부를 켜고 끄며, 새 일정 작성 시 미리 선택될 기본값(중요도·유형)을 지정한다
- Action:
  - **전역 알림 사용 토글**: 설정에서 "알림 사용" 스위치를 on/off 한다. 기본값 **on**.
  - **새 일정 기본 중요도**: 설정에서 새 일정 작성 시 기본 선택될 우선순위(높음/보통/낮음)를 지정한다. 지정하지 않으면 "보통".
  - **새 일정 기본 유형**: 설정에서 새 일정 작성 시 기본 선택될 유형을 지정한다(F-06 유형 목록에서 선택). 지정하지 않으면 "기타".
  - 설정 화면에는 "유형 관리" 화면(F-06) 진입점도 함께 둔다.
- Result:
  - 전역 알림 사용이 **off**이면: 이후 저장/수정되는 모든 일정에 대해 사전 알림(F-08)·정시 알림(F-09)을 **예약하지 않는다**. 이미 예약되어 있던 알림은 **취소한다**(P-32, D-07 기본안).
  - 전역 알림 사용을 다시 **on**으로 바꾸면: 이후 저장/수정되는 일정부터 각 일정의 알림 설정대로 다시 예약된다. (이미 존재하는 일정의 일괄 재예약 여부는 D-07)
  - 새 일정 기본값을 지정하면: 일정 작성 화면(F-01) 진입 시 중요도·유형 필드가 해당 기본값으로 미리 선택된 상태로 표시된다. 사용자는 저장 전 자유롭게 변경할 수 있다.
  - 설정 변경은 즉시 저장되고 앱 재실행 후에도 유지된다(F-15).
- 정책 관계:
  - P-32(전역 알림 토글)와 P-10-1(알림 본문 제목 노출 토글)은 **독립**이다. 전역 알림이 off면 알림 자체가 없으므로 P-10-1은 무효(적용 대상 없음). 전역 알림이 on일 때만 P-10-1이 개별 알림 본문에 적용된다.
  - 새 일정 기본값은 **작성 화면의 초기 선택값만** 바꾼다. 저장 시 검증·저장 규칙(E-07-1, E-06-1)은 그대로다. 기본값이 지정되어 있으면 E-07-1/E-06-1의 "미선택" 상황은 사실상 발생하지 않는다(초기값이 채워져 있으므로).
  - 기본 유형으로 지정한 유형이 이후 삭제되면(F-06 E-06-2) 기본 유형 설정은 "기타"로 되돌아간다(P-33).
- Exception:
  - E-18-1 전역 알림 사용을 켰으나 OS 알림 권한이 거부 상태 → F-08 E-08-1과 동일하게 앱 내 안내·설정 이동 유도. 앱 설정값은 on으로 저장되며 권한 허용 시 실제 예약이 동작한다.
  - E-18-2 새 일정 기본 유형으로 지정하려는 유형이 존재하지 않음(동기화 등으로 사라짐) → 기본 유형을 "기타"로 자동 대체
  - E-18-3 설정 저장 실패 → 이전 값으로 롤백하고 재시도 안내

### F-19 애플워치(watchOS) 워치 앱 (확정 — NFR-10 승격에 의한 신규 요구사항)

**목적 / 배경**

- 코어 도메인 계층(`src/core`, 플랫폼 비의존 순수 TS)이 이미 분리되어 있어 워치에서 재사용 준비가 되어 있다. 이를 활용해 "오늘 할 일 확인 + 완료 체크"라는 가장 빈번한 동작을 손목에서 즉시 수행하게 한다.
- 설계 문서상 "후속 과제(NFR-10 / `document/architect/nfr.md` N-8)"였던 워치 타깃을 이번 릴리스에서 **착수 상태로 승격**한다.
- 워치는 폰 앱의 **축소 어댑터**이며 읽기 + 완료 토글에 한정한다. 독립 저장소를 갖지 않는다(A-2).
- 사용자 신규 요청: "애플워치(watchOS) 워치 타깃 추가".

**기본 정의**

- Who: 아이폰 "오늘뭐해" 앱과 페어링된 애플워치 착용자.
- When: 워치에서 워치 앱을 열었을 때 / (D-10 결정 시) 워치 페이스 컴플리케이션에서 진입했을 때.
- What: 오늘 일정 목록과 각 일정의 최소 상세를 조회하고, 완료/미완료를 토글한다.
- Action: 목록을 스크롤하여 훑고, 완료 컨트롤을 탭해 완료/미완료를 뒤집고, 수동으로 새로고침한다.
- Result / Exception: 아래.

**표시 요소 (확정)**

- 오늘(단말 로컬 자정 기준, P-17) 일정 목록을 시작 시각순으로 표시한다.
- 각 항목 최소 상세: **제목 / 시작 시각 / 유형(라벨 또는 색) / 완료·미완료 상태**. 중요도는 **표식 수준**("높음"만 강조 표시)으로 한다.
- 목록 헤더에 오늘 요약 카운트(완료 수 / 미완료 수)를 표시한다.
- (선택 표시) **다음 예정 일정 1건**을 목록 상단 또는 별도 영역에 요약 표시한다.
- 지난(시작 시각 경과·미완료) 일정은 폰과 동일하게 표시상 구분한다(§7.6 상태 규칙 재사용).

**상호작용 (확정)**

- **완료/미완료 토글**: 목록 항목의 완료 컨트롤을 조작해 완료 상태를 뒤집는다. F-05 규칙(완료 시각 기록, 즉시 저장, 집계 반영)을 그대로 따르며, 변경은 폰으로 역전파된다(P-36).
- 목록 스크롤, **수동 새로고침**(당겨서 새로고침 등).
- 그 외 동작(생성·수정·삭제·스누즈·유형 관리·검색·설정 변경·테마 변경·캘린더 연동 설정)은 **워치 비범위**이며 폰에서만 가능하다. 워치에는 해당 진입점을 두지 않거나, 두더라도 "폰에서 계속" 안내로만 연결한다(P-43).

**진입 형태**

- **워치 앱 본체 화면**을 기본 진입 형태로 한다(확정).
- 워치 페이스 **컴플리케이션** 노출(예: "오늘 남은 일정 수")은 이번 범위에서 **D-10으로 유보**한다(포함/후속 결정 대기). 기본 가정: 컴플리케이션은 "오늘 남은(미완료) 일정 수" 1종만 제공하고, 탭 시 워치 앱을 실행하는 것 외의 상호작용은 두지 않는다(P-42). 미결 시 후속(OI-12).
- 워치 알림은 F-08 / F-09 / P-41을 따른다(워치 앱이 독립 예약하지 않음).

**Result**

- R-19-1 워치 앱을 열면 폰과 동기화된 "오늘 + 다음 예정 1건" 스냅샷이 표시된다(마지막 동기화 시점 데이터, 오프라인 허용).
- R-19-2 워치에서 완료 토글 시 워치 화면의 요약 카운트가 즉시 갱신되고, 변경은 폰으로 역전파되어 폰 대시보드 집계에도 반영된다(AC-23 확장 / AC-48).
- R-19-3 폰에서 일정이 추가·수정·삭제·완료되면 다음 갱신 시점(P-37)에 워치 목록에 반영된다.
- R-19-4 폰↔워치가 주고받는 시각 값은 코어와 동일하게 **epoch milliseconds + IANA time zone 식별자**로 표현하고, 워치는 표시 시점에만 로컬 시간대로 변환한다(P-39).

**Exception**

- E-19-1 워치가 폰과 연결 불가(블루투스/도달 불가) → 마지막으로 받은 스냅샷을 "최신 아님" 표시와 함께 조회 전용처럼 보여준다. 이 상태의 완료 토글은 워치에 **보류 큐**로 저장했다가 연결 복구 시 폰으로 전송한다(P-38).
- E-19-2 폰 앱이 미설치 / 로그아웃 / 초기화 상태 → 워치 앱은 "폰 앱에서 설정을 완료해 주세요" 취지의 안내만 표시한다.
- E-19-3 워치 보류 변경과 폰의 최신 상태가 충돌(같은 일정을 양쪽에서 변경) → **마지막 쓰기 우선(Last-Write-Wins)** 원칙으로 해소한다. 완료/미완료 상태는 더 나중의 변경 타임스탬프 값을 최종값으로 채택한다(P-38).
- E-19-4 워치에서 참조하는 유형이 폰에서 삭제됨 → 해당 일정은 기본 유형("기타")으로 표시한다(E-06-2 준용).
- E-19-5 오늘 일정 0건 → "오늘 일정이 없습니다" 빈 상태를 표시한다. 일정 추가 버튼은 두지 않는다(생성은 폰 전용).
- E-19-6 동기화 대상 일정이 많음 → 워치로는 "오늘 일정 + 다음 예정 1건" 범위만 전송하여 페이로드를 제한한다(P-40). 전체 일정·과거 이력·검색 인덱스는 워치로 미러링하지 않는다.
- E-19-7 워치 알림 표시 → F-08 / F-09 / P-41을 따른다. 워치 앱은 알림을 독립 예약하지 않으며, 전역 "알림 사용" off(P-32)이면 워치에도 알림이 노출되지 않는다.

**F-19 비범위 (Out of scope)**

- **Android Wear OS 워치 앱** — 이번 범위 제외, 후속(OI-11). Android는 Wear Data Layer 사용이 예상되나 설계·구현 모두 이번 릴리스에서 다루지 않는다.
- 워치 단독 일정 생성·수정·삭제·스누즈, 워치 검색, 워치 설정·유형 관리 화면.
- 워치 앱의 독립적 로컬 알림 예약(P-41: 폰이 예약 주체).
- 워치용 브랜드 로딩 오리 애니메이션(E-17-6, OI-7) — 워치 표준 로딩 표시를 사용한다.
- 컴플리케이션 다종·커스터마이즈, 워치 페이스 위젯 스타일 선택 — D-10 미결 또는 후속(OI-12).
- **기술 선택**: 워치 타깃 구성 방식, RN watchOS 지원 여부, 네이티브 브리지 / WatchConnectivity 전송 방식, 코어 로직의 워치 번들링 방법 — 전부 Architect 설계 범위이며 본 기획에서 확정하지 않는다.

**NFR-10 승격 명시**

- 본 F-19로 NFR-10(이식성 — 워치 앱은 모바일과 데이터 스키마·동기화 규약 공유)의 상태를 "후속(가정 A-2)"에서 **"이번 릴리스 착수"** 로 올린다.
- `document/architect/nfr.md`의 워치 관련 후속 검증 항목(§3 확장성 / §8 이식성 / §11.2 환경 외 후속 검증 / §12 N-8)과 연계된다. 본 기획은 **연계 사실만 명시**하며, `nfr.md`를 포함한 설계 문서 및 소스 코드 수정은 Architect / Developer 단계에서 수행한다(본 개정은 `plan.md`만 변경).

### F-20 대시보드 날짜 탐색 (확정 — 사용자 신규 요청, v1.5 / v1.6 "작게" 요건 추가)

**목적 / 배경**

- 사용자가 대시보드("오늘" 탭)를 벗어나지 않고 어제·내일 등 인접 날짜의 일정 현황을 빠르게 확인하게 한다.
- 사용자 요청 원문: "오늘 메뉴에서 오늘을 기준으로 화살표로 어제, 내일을 볼수있도록 하고".

**기본 정의**

- Who: 개인 사용자
- When: 대시보드 화면을 보고 있을 때 언제든
- What: 대시보드가 표시하는 "기준 날짜"를 하루 단위로 앞뒤로 이동한다. 기본 기준 날짜는 오늘(단말 로컬 자정 기준, P-17).
- Action:
  - 상단 날짜 표시 영역의 **좌 화살표**를 탭 → 기준 날짜를 전날로 이동한다.
  - **우 화살표**를 탭 → 기준 날짜를 다음날로 이동한다.
  - 기준 날짜가 오늘이 아닐 때 노출되는 **"오늘로" 복귀 컨트롤**(날짜 라벨 탭 또는 별도 버튼 — 구체 형태는 설계)을 탭 → 기준 날짜를 오늘로 즉시 되돌린다.
- Result:
  - 기준 날짜가 바뀌면 진행률 한 줄(F-21), 오늘 일정 리스트 영역(F-10), 요약 상세 영역이 모두 새 기준 날짜의 데이터로 갱신된다.
  - 날짜 표시 영역에는 이동한 날짜가 사람이 읽을 수 있는 형식(예: "9월 8일 (월)", 로캘 대응 NFR-09)으로 표시되고, 오늘일 때는 "오늘" 표기를 함께 보여준다.
  - 기준 날짜가 오늘이 아니면 "오늘로" 복귀 컨트롤이 노출되고, 오늘이면 숨겨진다.
  - **시각적 크기(v1.6 확정)**: 날짜 네비게이션 영역은 대시보드에서 **시각적으로 작게(컴팩트하게)** 배치한다 — 화살표·날짜 라벨·"오늘로" 컨트롤을 한 줄에 담고, 그 아래 진행률 한 줄(F-21)·리스트가 화면 상단 공간을 차지하도록 한다. 구체 높이·타이포·아이콘 크기는 설계에서 확정한다(OI-15 관련).
- Exception:
  - E-20-1 날짜 이동 범위 경계 → 가정상 무제한 이동을 허용한다(D-13). 범위 제한을 두기로 하면 경계에서 해당 방향 화살표를 비활성화한다.
  - E-20-2 이동한 날짜의 데이터 로드 실패 → 날짜 표시·화살표는 유지하고 목록/진행률 한 줄 영역에 재시도 안내를 표시한다(F-02 E-02-2 / F-10 E-10-6 준용).
  - E-20-3 오늘이 아닌 날짜를 보는 중 자정 경과 → 보고 있던 기준 날짜(달력상 날짜)는 그대로 유지한다. "오늘"의 정의만 하루 넘어가며, "오늘로" 복귀 시 새 오늘로 이동한다(P-46).
  - E-20-4 화살표를 연속으로 빠르게 탭 → 각 탭은 1일씩 누적 이동하며, 중간 로딩이 조작을 막지 않는다(디바운스/큐잉 세부는 설계).
  - E-20-5 대시보드 탭을 벗어났다가 다시 진입 / 앱 재시작 → 기준 날짜는 오늘로 리셋된다(D-12 가정, P-45).

**F-20 비범위**

- 주간/월간 미니 캘린더, 스와이프 제스처로의 날짜 이동, 날짜 직접 선택(date picker) — 이번 범위는 좌/우 화살표 + "오늘로" 복귀만(OI-15).
- 캘린더 탭(F-02 일간/주간/월간 뷰)의 변경 — 이번 개선은 대시보드 화면에 한정한다.

### F-21 대시보드 진행률 한 줄 (확정 — 조정자 재확정 방향, v1.6 / v1.5 "개수 카드"에서 재정의)

**목적 / 배경**

- 선택된 날짜에 "얼마나 있고 / 얼마나 끝냈는지"를 시선이 먼저 닿는 위치에 **한 줄 요약**으로 제시한다.
- 사용자 요청 원문: "아래에 오늘의 총 일정과 완료일정 개수는 카드형식으로 하고". → 조정자가 방향을 재확정하여, **개수 카드 2장** 대신 **"M / N 완료" 형식 텍스트 + 얇은 progress bar 1개**의 한 줄 요약으로 확정한다(v1.6).
- 카드 2장은 세로 공간을 많이 쓰고 진척도(비율)를 직관적으로 못 보여준다는 판단. 한 줄 + progress bar는 공간 절약 + 진척도 즉시 인지.

**기본 정의**

- Who: 개인 사용자
- When: 대시보드 화면 표시 중
- What: 날짜 네비게이션 영역(F-20) 바로 아래에, 기준 날짜의 진행 상황을 **한 줄**로 표시한다 — **"M / N 완료" 형식 텍스트**(M=완료 일정 수, N=총 일정 수) + 그 진척 비율을 나타내는 **얇은 progress bar 1개**.
- Action: 사용자는 별도 조작을 하지 않는다(표시 전용). 한 줄 탭으로의 화면 이동은 이번 범위 밖(OI-16).
- Result:
  - 진행률 한 줄은 **"M / N 완료" 텍스트 + progress bar 1개**로 구성한다. progress bar의 채움 비율은 완료율(P-07: 완료 수 / 총 수, 총 0건이면 0%)과 같다. 텍스트·바의 세부 서식(색·두께·퍼센트 병기 여부)은 설계.
  - **미래 날짜 규칙(P-52, v1.6 신규 — 가정, D-19)**: 기준 날짜가 오늘보다 미래(로컬 자정 기준 비교)이면 **완료율·완료 수·progress bar를 표시하지 않고 총 일정 수만** 표시한다(예: "일정 N건"). 과거·오늘 날짜에서는 "M / N 완료" + progress bar를 모두 표시한다.
  - 집계 기준일은 기준 날짜(F-20)이며, 집계 규칙(어떤 일정을 그 날짜에 속한 것으로 볼지, 총/완료 수 산출)은 기존 F-10 요약 영역의 규칙을 그대로 사용한다(P-17 로컬 자정~다음 자정 경계, 시작 시각 기준 — 세부는 P-47). **v1.5 대비 집계 규칙 자체는 변경 없음.**
  - 완료 토글(F-05 / F-10 인라인), 스와이프 삭제(F-04 / F-10), 일정 추가 등으로 목록이 변하면 진행률 한 줄의 수치·progress bar가 실시간 갱신된다.
  - 이 한 줄은 기존 F-10 "요약 영역"의 카운트 표현을 대체·구체화하는 것이며, 요약 상세 영역의 나머지 표시요소(완료율(%)·유형별 분포·다음 예정 일정)와 상단 브랜드 영역(로고·태그라인, F-16)은 제거하지 않는다(AC-46 회귀 방지). 완료율(%)은 요약 상세 영역에서 계속 제공한다.
- Exception:
  - E-21-1 기준 날짜(과거·오늘) 일정 0건 → "0 / 0 완료" + 빈 progress bar(0%, P-07)로 표시한다. 한 줄 영역 자체는 계속 표시한다. (목록 영역은 E-10-1 빈 상태 안내)
  - E-21-2 집계 로드 실패 → 진행률 한 줄 영역에 재시도 안내를 표시하고 브랜드·날짜 네비 영역은 유지한다(F-10 E-10-6 준용).
  - E-21-3 접이식 검색(F-22)이 펼쳐져 검색어가 활성이어도 진행률 한 줄의 수치·progress bar는 기준 날짜 전체 기준을 유지한다(검색 결과 건수로 바뀌지 않는다). P-49, D-16.
  - E-21-4 (v1.6 신규) 기준 날짜가 미래 → progress bar·완료율·완료 수를 숨기고 총 일정 수만 표시한다(P-52). 미래 날짜 일정 0건이면 "일정 없음" 취지로 표시하고, 목록 영역은 E-10-1을 따른다. 기준 날짜를 오늘·과거로 되돌리면 "M / N 완료" + progress bar 표시가 복원된다.

### F-22 대시보드 접이식 날짜별 검색 (확정 — 조정자 재확정 방향, v1.6 / v1.5 "상시 인라인 검색"에서 재정의)

**목적 / 배경**

- 특정 날짜에 일정이 많을 때, 전역 검색(F-11)으로 화면을 옮기지 않고 그 날짜 목록 안에서 바로 항목을 좁혀 찾게 한다.
- 사용자 요청 원문: "바로 아래에 검색기능을 만들어 오늘일정에서 검색할 수 있게 해줘". → 조정자가 방향을 재확정하여, **상시 노출 입력창** 대신 **검색 아이콘을 탭하면 펼쳐지는 접이식(collapsible) 입력창**으로 확정한다(v1.6). 평소에는 아이콘만 노출되어 화면을 아끼고, 필요할 때만 입력창을 펼친다.

**기본 정의**

- Who: 개인 사용자
- When: 대시보드 화면 표시 중, 기준 날짜(F-20)의 일정 목록이 있는 상태
- What: 진행률 한 줄(F-21)과 오늘 일정 리스트 사이에 있는 **검색 아이콘**을 탭하면 펼쳐지는 검색 입력창에 검색어를 입력해, **기준 날짜의 일정 목록 안에서만** 항목을 필터링한다.
- Action:
  - **검색 아이콘을 탭한다** → 검색 입력창이 펼쳐지고(collapsible expand) 입력 포커스가 이동한다.
  - 펼쳐진 입력창에 텍스트를 입력한다 → 아래 "오늘 일정 리스트"가 입력에 따라 실시간(반영 지연·디바운스는 설계)으로 필터링된다.
  - 입력창의 **지우기(clear) 컨트롤**을 탭하거나 입력을 모두 지우면 검색어가 비워지고 기준 날짜의 전체 목록이 복원된다(입력창은 펼친 상태 유지).
  - **검색 아이콘을 다시 탭하거나 접기 컨트롤을 탭한다** → 입력창이 접힌다. 접힘 시 검색어·필터 처리는 D-18을 따른다(가정: 접으면 검색어 초기화 + 목록 필터 해제).
- Result:
  - **펼침/접힘 상태는 대시보드 로컬 상태**로 관리한다(기본값 = 접힘, P-53). 대시보드 탭 이탈 후 재진입·앱 재시작 시 접힌 상태로 리셋된다. 영구 저장하지 않는다.
  - **펼침 트리거(검색 아이콘)의 위치는 진행률 한 줄과 리스트 사이**로 고정한다.
  - 검색 대상 범위는 **기준 날짜에 속한 일정만**이다(P-47과 동일 집합). 다른 날짜 일정·전역 일정은 대상이 아니다.
  - 검색 대상 필드는 **제목 + 메모(내용)** 로 한다(대소문자·앞뒤 공백 무시). 유형명 포함 여부는 D-15(가정: 미포함, 유형은 기존 유형 필터/전역 검색이 담당).
  - 필터링은 리스트 영역에만 적용된다. 진행률 한 줄(F-21)의 수치·progress bar와 요약 상세 영역은 기준 날짜 전체 기준을 유지한다(P-49, D-16).
  - 필터된 목록에서도 완료 토글(F-10)·스와이프 삭제(F-10)·본문 탭 상세 이동은 그대로 동작한다.
  - 최소 글자 수는 1자로 한다(F-11 P-11과 일관).
- Exception:
  - E-22-1 (검색창이 펼쳐지고 검색어가 있는 상태에서) 검색 결과 0건 → 리스트 영역에 "검색어에 해당하는 오늘 일정이 없습니다" 취지의 빈 결과 안내와 검색어 지우기 유도를 표시한다. "그 날짜에 일정이 아예 없음"(E-10-1)과는 문구로 구분한다.
  - E-22-2 검색창이 펼쳐지고 검색어가 입력된 상태에서 좌/우 화살표 날짜 이동(F-20) → 검색어를 유지한 채 새 기준 날짜 목록에 재적용한다(P-50, D-17). "오늘로" 복귀·대시보드 탭 이탈·앱 재시작 시에는 검색어를 초기화하고 검색창을 접는다.
  - E-22-3 검색어 활성 중 완료 토글/스와이프 삭제/자동 갱신으로 목록이 바뀜 → 현재 검색어 기준 필터를 재적용한 결과로 목록을 갱신한다(검색 조건이 임의로 풀리지 않는다).
  - E-22-4 검색어가 공백만 → 검색을 적용하지 않고 전체 목록을 표시한다(빈 결과로 처리하지 않는다).
  - E-22-5 기준 날짜 일정 0건 → 우선 E-10-1 빈 상태 안내를 표시한다. 검색 아이콘의 노출/비활성 처리 세부는 설계(가정: 아이콘은 계속 노출하되 펼침 시 "검색할 일정이 없습니다" 취지 안내).
  - E-22-6 (v1.6 신규) 검색창을 **접으면** → D-18 가정값에 따라 검색어를 초기화하고 목록 필터를 해제한다(전체 목록 복원). D-18이 "유지"로 확정되면 검색어·필터를 보존하고 다시 펼칠 때 복원한다.
  - E-22-7 (v1.6 신규) 검색창이 펼쳐진 상태로 대시보드 탭을 벗어났다가 재진입 / 앱 재시작 → 검색창은 접힌 상태로 복귀하고 검색어는 초기화된다(P-53, P-50).

**F-22 비범위**

- 유형/완료여부/우선순위/기간 등 필터 컨트롤 — 이번 범위는 텍스트 검색만(OI-17). 필요 시 전역 검색(F-11)을 사용한다.
- 다른 날짜·전역 범위 검색, 접이식 검색 결과의 전역 검색 화면 연계 — F-11이 담당(OI-18).
- 검색 아이콘의 펼침/접힘 애니메이션·모션 세부, 아이콘의 정확한 배치·크기 — 설계(OI-20).
- 검색 기록/추천어/결과 하이라이트 표시 — 후속.

## 5. 정책 및 규칙

### 5.1 반복 일정 (가정 — 원본 미명시, 범위 한정)

- **P-01**: 이번 릴리스는 **없음/매일/매주/매월/매년**의 단순 반복만 지원한다. 종료 조건은 "종료일" 또는 "N회".
- **P-02**: 반복 일정의 개별 회차를 수정/삭제하면 "이 일정만 / 이후 모두"를 선택한다.
- **P-03**: 반복 일정의 알림은 각 회차마다 독립적으로 예약된다(향후 일정 범위 내에서만 실제 예약, 나머지는 도래 시 재예약).

### 5.2 완료 상태

- **P-04**: 완료 여부는 일정당 1개의 불리언 + 완료 시각(nullable)으로 관리한다.
- **P-05**: 완료된 일정도 수정 가능하며, 시간 변경 시 완료 상태는 유지된다.
- **P-06**: 미래 일정도 완료 체크할 수 있다(사용자 판단 존중).
- **P-07**: 대시보드 "완료율"은 (완료 수 / 전체 수) × 100, 전체 0건이면 0%로 표시.

### 5.3 캘린더 연동 / 중복

- **P-08**: 앱↔기본 캘린더 일정의 동일성 판정 = (외부 캘린더 이벤트 ID 매핑 존재) 우선, 없으면 (제목 + 시작시각 동일) 휴리스틱. 병합 시 사용자 편집(로컬) 필드를 보존.
- **P-08-1**: 캘린더에서 삭제된 외부 일정은 앱에서 "외부 삭제됨"으로 표시 후 다음 동기화에서 제거(가정).
- **P-08-2**: 충돌 해결 기본값은 "기기 캘린더 우선", 설정에서 "앱 우선"으로 변경 가능(가정).

### 5.4 알림

- **P-09**: 앱은 기기 재부팅·강제 종료 이후에도 미래 알림 예약을 복원한다(부팅 완료 시점 재예약).
- **P-10**: 한 일정의 사전 알림 오프셋은 최대 5개로 제한한다(가정).
- **P-10-1**: 알림 본문에 일정 제목 노출 여부는 사용자 설정으로 토글한다(민감정보 보호, 기본: 노출).

### 5.5 검색

- **P-11**: 검색 최소 글자 수는 1자. 2자 미만 검색은 결과 상한(예: 50건)과 함께 안내(가정).
- **P-12**: 검색 대상 필드 = 제목, 메모, 유형명. 완료/우선순위/기간은 필터로만.

### 5.6 계정 / 데이터

- **P-13**: 로그인 없이 모든 로컬 기능을 사용할 수 있어야 한다(계정은 선택).
- **P-14**: 계정 연동 해제 시 로컬 데이터는 삭제하지 않는다.
- **P-15**: 일정 제목/메모는 민감정보로 간주하고 로컬 저장 시 보호 수준을 설계 단계에서 정의한다(암호화 여부는 NFR/보안 설계에서 결정).

### 5.8 앱 아이덴티티 UI

- **P-18**: 탭 아이콘은 탭 라벨(텍스트)과 함께 표시한다. 아이콘만 표시하는 아이콘 전용 모드는 이번 범위 제외.
- **P-19**: 탭 아이콘 활성/비활성 구분은 투명도(tintColor) 또는 색상 필터로 구현한다. 아이콘 파일을 별도로 교체하지 않는다.
- **P-20**: 대시보드 헤더 로고·태그라인의 표시 크기는 화면 폭의 60% 이하로 제한하여 하단 콘텐츠를 가리지 않게 한다(가정: 구체 수치는 설계에서 확정).
- **P-21**: 에셋 파일 경로는 `src/assets/icons/`와 `src/assets/images/`로 고정한다. 빌드 타임에 번들에 포함된다.

### 5.9 브랜드 로딩 인디케이터 (F-17)

- **P-22**: 로딩 인디케이터는 앱 고유 표현(오리 캐릭터 애니메이션)을 기본으로 하되, 접근성·성능·실패 상황에서는 정적 폴백 → OS 표준 인디케이터 순으로 단계적으로 대체한다(E-17-1·E-17-2·E-17-5).
- **P-23**: 오리가 순환하는 활동은 최소 3개, 최대 5개로 한다. 활동은 이 앱 도메인(일정 확인·달력·알림·완료 체크·검색)에서 선정한다.
- **P-24**: 표시 지연(delay) 임계값을 둔다. 로딩 시작 후 이 시간(가정: 150~300ms) 안에 로딩이 끝나면 인디케이터를 표시하지 않는다(깜빡임 방지). 정확한 값은 설계에서 확정한다.
- **P-25**: 각 활동의 노출 시간은 가정 2~4초이며, 활동 간 전환은 급격한 점프 없이 연결되어야 한다. 정확한 값은 설계에서 확정한다.
- **P-26**: 인디케이터가 일단 표시되면 최소 표시 시간(가정: 500~800ms)을 보장한다. 그 전에 로딩이 끝나도 최소 시간까지 유지한 뒤 제거한다. 정확한 값은 설계에서 확정한다.
- **P-27**: 인라인 인디케이터는 화면 폭의 40% 이하, 풀스크린 인디케이터는 60% 이하 크기로 제한한다(구체 수치는 설계).
- **P-28**: 로딩 타임아웃 보조 안내 임계값(가정: 10초 이상)을 둔다. 초과 시 보조 문구·재시도/취소 안내를 함께 노출한다(E-17-4).
- **P-29**: 저사양 기기·배터리 절약 모드로 판정되면 정적 폴백으로 자동 전환한다. 판정 방법·기준은 설계(NFR)에서 정의한다.
- **P-30**: 인디케이터에는 "불러오는 중" 의미의 접근성 라벨을 제공한다. 활동이 바뀔 때마다 스크린리더로 반복 안내하지 않는다.
- **P-31**: 무한 루프 애니메이션은 로딩 종료(성공/실패) 시 반드시 정지·해제하여 리소스 누수를 방지한다.

### 5.7 시간/시간대

- **P-16**: 일정 시각은 단말 로컬 시간대를 기준으로 저장·표시한다. 시간대 변경 시 표시 규칙은 설계에서 정의(가정: 저장은 UTC + TZ, 표시는 로컬).
- **P-17**: 날짜 경계(자정)는 단말 로컬 자정을 기준으로 한다.

### 5.10 앱 설정 — 전역 알림 / 새 일정 기본값 (F-18, v1.3 신규)

- **P-32** (전역 알림 사용 토글): 앱은 전역 "알림 사용" 스위치를 제공하며 기본값은 **on**이다.
  - off인 동안 저장/수정되는 일정은 사전 알림(F-08)·정시 알림(F-09)을 예약하지 않는다.
  - off로 전환하는 시점에 이미 예약된 알림은 **모두 취소**한다(D-07 기본안. 대안: 앱 내부에 보류 상태로 남겨 두었다가 on 복귀 시 복원 — D-07에서 확정).
  - on으로 되돌리면 그 이후 저장/수정되는 일정부터 개별 알림 설정대로 재예약한다. 기존 전체 일정의 자동 일괄 재예약 여부는 D-07.
  - P-32는 개별 일정의 알림 설정값을 지우지 않는다(설정값은 보존, 예약 실행만 억제).
  - P-32(알림 자체의 on/off)와 P-10-1(알림 본문 제목 노출 여부)은 독립이다. 전역 알림 off면 P-10-1은 적용 대상이 없다.
- **P-33** (새 일정 기본값): 설정에서 새 일정 작성 시 기본 선택될 중요도(우선순위)와 유형을 지정할 수 있다.
  - 기본 중요도 미지정 시 "보통", 기본 유형 미지정 시 "기타"(기존 E-07-1 / E-06-1 규칙 유지).
  - 기본값은 일정 작성 화면(F-01)의 **초기 선택값**에만 영향을 준다. 저장 검증·저장 규칙은 변경하지 않는다.
  - 기본 유형으로 지정된 유형이 삭제되면 기본 유형 설정은 "기타"로 되돌린다.
  - 일정 수정(F-03) 화면에는 기본값을 적용하지 않는다(기존 저장값을 표시).

### 5.11 유형 관리 (F-06, v1.3 신규)

- **P-34** (기본 유형 보호 및 이름 규칙): 기본 유형 "기타"는 삭제·이름변경할 수 없다(해당 조작 비활성 또는 거부).
  - 유형 이름은 공백만으로 구성될 수 없다(앞뒤 공백 제거 후 1자 이상).
  - 유형 이름은 서로 중복될 수 없다(앞뒤 공백 제거 + 대소문자 무시 비교).
  - 일정은 유형을 **식별자(ID)로 참조**한다. 유형 이름변경은 참조를 유지한 채 표시 라벨만 바꾼다 → 해당 유형을 쓰는 모든 일정에 즉시 반영된다.
  - 유형 삭제 시 그 유형을 참조하던 일정은 기본 유형 "기타"로 재지정한다(E-06-2).
  - 유형별 색상/아이콘의 사용자 편집 여부는 이번 범위 밖이다(D-08). 이번 릴리스는 이름 추가·변경·삭제만 지원한다.

### 5.12 상호작용형 대시보드 (F-10, v1.3 재정의)

- **P-35**: 대시보드는 요약 영역과 "오늘 일정 목록" 영역을 한 화면에 함께 표시한다.
  - 목록에서의 완료 토글은 F-05 규칙을, 스와이프 삭제는 F-04 규칙(삭제 확인, 알림 예약 제거, 캘린더 연동 일정 P-08)을 그대로 따른다. 대시보드는 이 기능들의 추가 진입 경로일 뿐 새 규칙을 만들지 않는다.
  - 상단 브랜드 영역(로고·태그라인)과 요약 표시요소(완료율·유형별 분포·다음 예정)는 상호작용 목록 도입 이후에도 제거하지 않는다(F-16 / AC-25 회귀 방지).
  - 일정 추가 진입점은 상시 FAB로 제공하고, 금일 0건인 빈 상태에서는 목록 영역에 명시적 "일정 추가" 버튼도 함께 표시한다(AC-15).
  - (v1.5 / v1.6) 대시보드에 날짜 네비게이션 영역(F-20, 시각적으로 작게)·진행률 한 줄 영역(F-21)·접이식 검색 영역(F-22)이 추가되어도 상단 브랜드 영역과 요약 표시요소(완료율·유형별 분포·다음 예정)는 제거하지 않는다. 진행률 한 줄은 기존 카운트 표시의 표현을 "M / N 완료" 텍스트 + progress bar 1개로 바꾼 것이며 새 집계 규칙을 만들지 않는다(P-47). 화면 영역 순서는 브랜드 → 날짜 네비(작게) → 진행률 한 줄 → 접이식 검색 → 요약 상세 → 리스트 → FAB이다.

### 5.14 애플워치(watchOS) 워치 앱 (F-19, v1.4 신규)

- **P-36** (워치 데이터 소스·방향): 워치는 독립 저장소를 갖지 않는다(A-2). 폰(SQLite)이 유일한 원본(source of truth)이며, 폰은 워치로 "오늘 일정 + 다음 예정 1건"의 읽기용 스냅샷을 내려보낸다. 워치에서 폰으로 역전파되는 쓰기는 **완료/미완료 토글 1종**만 허용한다. 그 외 필드 변경은 워치에서 발생하지 않는다.
- **P-37** (갱신 시점): 워치 목록은 다음 시점에 갱신을 시도한다 — (1) 워치 앱 포그라운드 진입, (2) 사용자의 수동 새로고침, (3) 폰이 데이터 변경 후 보내는 백그라운드 전송 수신. 상시 실시간 스트리밍은 요구하지 않는다. 구체 트리거·주기 조합은 D-09.
- **P-38** (오프라인 동작·충돌 해소): 워치가 폰과 연결되지 않은 동안의 완료 토글은 워치의 보류 큐에 저장했다가 연결 복구 시 폰으로 전송한다. 동일 일정에 대해 워치 보류 변경과 폰 변경이 충돌하면 **마지막 쓰기 우선(Last-Write-Wins)** 원칙으로 해소하며, 완료 상태는 더 나중의 변경 타임스탬프 값을 최종값으로 한다. 원칙 수준만 확정하고 타임스탬프 정밀도·비교 세부는 설계에서 정의한다.
- **P-39** (시각 표현 공유): 폰↔워치가 주고받는 모든 시각 값은 코어와 동일하게 **epoch milliseconds + IANA time zone 식별자**로 표현한다. 로컬 시간대 변환은 워치 표시 계층에서만 수행한다(P-16과 일관).
- **P-40** (페이로드 범위 제한): 폰이 워치로 보내는 동기화 페이로드는 "오늘(로컬 자정 기준) 일정" + "다음 예정 1건"으로 제한한다. 과거 전체 이력·검색 인덱스·전체 유형 정의의 미러링은 하지 않는다(표시에 필요한 유형 라벨·색만 함께 전달).
- **P-41** (알림 예약 주체는 폰): 일정 알림(F-08 사전 / F-09 정시)의 예약·발송 주체는 **폰**이다. 워치 앱은 알림을 독립적으로 예약하지 않는다. 페어링된 워치에서의 알림 노출은 iOS의 기존 알림 미러링 동작에 위임하며, 앱은 이를 우회하거나 중복 생성하지 않는다. 전역 "알림 사용" off(P-32)이면 워치에도 알림이 노출되지 않는다.
- **P-42** (워치 컴플리케이션): 워치 페이스 컴플리케이션 제공 여부는 D-10으로 유보한다. 제공하기로 결정되면 이번 범위는 "오늘 남은(미완료) 일정 수" **1종**으로 한정하고, 탭 시 워치 앱을 실행하는 것 외의 상호작용은 두지 않는다. 미결 시 후속(OI-12).
- **P-43** (워치 상호작용 경계): 워치에서 제공하는 사용자 조작은 (a) 오늘 일정 목록 조회, (b) 개별 일정 최소 상세 조회, (c) 완료/미완료 토글, (d) 수동 새로고침 4가지로 한정한다. 생성·수정·삭제·스누즈·검색·유형 관리·설정/테마/캘린더 연동 변경은 워치에서 제공하지 않는다.
- **P-44** (플랫폼 경계): F-19의 이번 릴리스 대상은 **애플워치(watchOS)** 로 한정한다. Android Wear OS 워치 앱은 이번 범위 밖이며 후속으로 분리한다(OI-11). Android Wear Data Layer는 후속 설계의 참고 사항일 뿐 이번 릴리스에서 구현하지 않는다.

### 5.15 대시보드 날짜 네비게이션 · 진행률 한 줄 · 접이식 날짜별 검색 (F-20 / F-21 / F-22, v1.5 신규 / v1.6 재확정 방향 개정)

- **P-45** (대시보드 기준 날짜 상태): 대시보드는 "기준 날짜" 상태를 하나 갖는다. 기본값은 오늘(P-17). 좌/우 화살표로 ±1일 이동하고 "오늘로" 복귀 컨트롤로 즉시 오늘로 되돌린다. 대시보드 탭을 벗어났다가 재진입하거나 앱을 재시작하면 기준 날짜는 오늘로 리셋된다(D-12 가정). 기준 날짜는 로컬에 영구 저장하지 않는다.
- **P-46** (자정 경과와 기준 날짜): 기준 날짜가 "그 시점의 오늘"이었으면 자정 경과 시 새 오늘로 함께 이동한다(E-10-2 확장). 기준 날짜가 오늘이 아닌 다른 날이었으면 자정 경과에도 그 달력상 날짜를 유지하고, "오늘로" 복귀 시 새 오늘로 간다.
- **P-47** (진행률 한 줄 지표·집계 규칙): 진행률 한 줄은 기준 날짜의 **완료 일정 수(M)**와 **총 일정 수(N)**를 "M / N 완료" 텍스트 + progress bar 1개로 표시한다. "그 날짜에 속한 일정"의 판정은 기존 F-10 요약 영역과 동일한 규칙(시작 시각이 그 날짜의 로컬 자정~다음 자정 사이)을 사용한다. 완료 수는 그 집합 중 완료 상태(P-04)인 건수다. progress bar 채움 비율·완료율(%)은 P-07을 따르며 완료율(%)은 기존 요약 상세 영역에서 계속 제공한다. **v1.5 대비 집계 규칙 자체는 변경 없음**(표현만 "카드 2장" → "한 줄 + progress bar"로 재정의). 미래 날짜 표시 규칙은 P-52.
- **P-48** (접이식 검색 범위·대상): 대시보드 접이식 검색의 대상 집합은 **기준 날짜에 속한 일정만**이다(P-47과 동일 집합). 검색 대상 필드는 제목·메모(내용)이며 대소문자·앞뒤 공백을 무시한다. 유형명 포함 여부는 D-15. 최소 글자 수 1자(F-11 P-11과 일관). 실시간 반영의 디바운스·결과 정렬은 설계에서 정의한다.
- **P-49** (접이식 검색과 진행률 한 줄·요약의 독립): 접이식 검색은 대시보드 "오늘 일정 리스트" 영역의 표시만 필터링한다. 진행률 한 줄(F-21)의 수치·progress bar와 요약 상세 영역(완료율·유형별 분포·다음 예정)은 검색과 무관하게 기준 날짜 전체를 기준으로 유지한다(D-16).
- **P-50** (검색어 생명주기): 접이식 검색어는 좌/우 화살표 날짜 이동 시 유지되어 새 기준 날짜 목록에 재적용된다. "오늘로" 복귀, 대시보드 탭 이탈 후 재진입, 앱 재시작 시에는 초기화되고 검색창은 접힌다(D-17, P-53). 검색어는 영구 저장하지 않는다.
- **P-51** (전역 검색과의 관계): 대시보드 접이식 검색(F-22)과 검색 탭의 전역 검색(F-11)은 서로 독립이다. 한쪽의 검색어·필터가 다른 쪽에 전파되지 않는다.
- **P-52** (미래 날짜 진행률 표시 — v1.6 신규, 가정 / D-19): 기준 날짜가 오늘보다 미래(로컬 자정 기준 비교)이면 진행률 한 줄은 **완료율·완료 수·progress bar를 표시하지 않고 총 일정 수만** 표시한다(예: "일정 N건"). 과거·오늘 날짜에서는 "M / N 완료" + progress bar를 모두 표시한다. 근거: 아직 도래하지 않은 날의 "완료 0 / N" 및 progress bar 0%가 진척 부진으로 오인될 수 있어, 미래 날짜에서는 "무엇이 얼마나 예정되어 있는지"만 전달한다. (F-05/P-06으로 미래 일정을 미리 완료 체크할 수는 있으나, 진행률 한 줄에는 그 완료 수를 반영하지 않는다 — 요약 상세 영역의 완료율은 기존대로 산출.) 이해관계자 추인 대상(D-19, 비차단).
- **P-53** (접이식 검색 펼침/접힘 상태 — v1.6 신규): 대시보드 접이식 검색의 펼침/접힘은 대시보드 로컬 상태로 관리하며 기본값은 **접힘**이다. 검색 아이콘 탭으로 펼치고, 아이콘 재탭 또는 접기 컨트롤로 접는다. 대시보드 탭 이탈 후 재진입·앱 재시작 시 접힌 상태로 리셋된다. 펼침/접힘 상태는 영구 저장하지 않는다. 접힘 시 검색어·필터 처리는 D-18(가정: 접으면 검색어 초기화 + 필터 해제).

## 7. 사용자 흐름 (User Flow)

### 7.1 최초 실행

1. 앱 실행 → 온보딩(간단 소개)
2. 알림 권한 요청(건너뛰기 가능)
3. (선택) 캘린더 접근 권한 요청
4. (선택) 계정 로그인
5. 대시보드(빈 상태) 진입 → 상단 로고·태그라인 표시 + 요약(0/0/0%) + 목록 영역 "오늘 일정이 없습니다" 안내와 "일정 추가" 버튼 + 상시 FAB (F-16 / F-10 / AC-15)

### 7.2 일정 등록 → 알림 → 완료 (핵심 흐름)

1. 대시보드 FAB 또는 캘린더 "+" → 일정 작성 화면
2. 제목·일시·유형·우선순위·메모 입력 (중요도·유형은 설정된 새 일정 기본값 P-33이 미리 채워져 있을 수 있음)
3. 사전 알림 오프셋 선택(예: 10분 전, 1일 전) + 정시 알림 on
4. 저장 → 검증 통과 → SQLite 저장 → (전역 알림 사용 on일 때 P-32) 알림 예약
5. 오프셋 시각/정시에 로컬 알림 수신(모바일·워치)
6. 대시보드 "오늘 일정 목록"에서 항목의 체크박스를 직접 탭해 완료 토글 (또는 알림/상세에서 토글)
7. 요약(완료 수·완료율·유형별 분포) 실시간 갱신
8. (선택) 대시보드 목록에서 항목을 스와이프해 삭제 → 확인 → 일정·알림 예약 제거, 목록·요약에서 사라짐

### 7.3 검색

1. 검색 탭 → 검색어 입력
2. (선택) 유형/완료/기간 필터
3. 결과 목록 → 항목 선택 → 상세/수정

### 7.4 캘린더 연동

1. 설정 → 캘린더 연동 → 권한 동의
2. 가져올 캘린더 선택, 동기화 방향 설정
3. 외부 일정이 앱 뷰에 병합 표시(P-08)
4. 충돌/중복은 규칙에 따라 병합 또는 사용자 선택

### 7.5 계정 연동 (D-01 결정 전 기본 흐름)

1. 설정 → 계정 → 로그인(OAuth)
2. 동의 → 연동 완료 표시
3. (D-01=(a)면) 기기 간 동기화 시작 / (D-01=(c)면) 캘린더 연동 활성화만

### 7.6 상태 전이 (일정)

```
[작성중] --저장--> [예정]
[예정] --완료토글--> [완료]
[완료] --완료토글--> [예정]
[예정/완료] --수정--> (같은 상태 유지, 알림 재예약)
[예정/완료] --삭제--> [삭제됨] (알림 예약 제거)
[예정] --시작시각 경과 & 미완료--> [지남(미완료)]  (표시상 구분, 완료 토글 계속 가능)
```

### 7.7 로딩 대기 (F-17)

1. 사용자가 앱을 실행(부트스트랩)하거나 대시보드/캘린더/검색에서 데이터 요청이 발생한다.
2. 로딩 상태 진입 → 표시 지연 임계(P-24) 경과까지 대기.
3. 여전히 로딩 중이면 오리 캐릭터 애니메이션 표시(부트스트랩=풀스크린 중앙, 그 외=콘텐츠 영역 인라인 소형).
4. 오리가 활동을 순환한다: 일정 확인 → 달력 넘기기 → 알림 종 울리기 → 완료 체크 (→ 검색하기).
5. 종료 분기:
   - 5-a 로딩 성공 → 최소 표시 시간(P-26) 보장 후 인디케이터 제거 → 실제 콘텐츠 표시.
   - 5-b 로딩 실패 → 인디케이터 즉시 제거 → 재시도 경로가 있는 에러 UI 표시.
   - 5-c 로딩 지연(P-28 초과) → 애니메이션 유지 + 보조 문구·재시도/취소 안내 노출.
6. 대체 분기: OS 동작 줄이기 켜짐 / 렌더 실패 / 저사양·절전 → 3~4단계 대신 정적 폴백(정지 오리 + "불러오는 중…") 표시.

### 7.8 유형(카테고리) 관리 (F-06)

1. 설정 → "유형 관리" 진입.
2. 현재 유형 목록 표시(기본 유형 "기타" 포함, "기타"는 삭제·이름변경 불가 표시).
3. 추가: "새 유형" → 이름 입력 → 저장. 빈 이름/중복 이름이면 거부·안내(E-06-3/E-06-4).
4. 이름변경: 유형 선택 → 새 이름 입력 → 저장. 검증 통과 시 그 유형을 쓰는 모든 일정 표시 라벨이 즉시 갱신(P-34, AC-39).
5. 삭제: 유형 선택 → 삭제 → 확인. 그 유형을 쓰던 일정은 "기타"로 재지정(E-06-2).
6. 완료 후 설정으로 복귀. 변경은 즉시 저장·재실행 후 유지.

### 7.9 앱 설정 — 전역 알림 / 새 일정 기본값 (F-18)

1. 설정 화면 진입.
2. "알림 사용" 스위치 토글:
   - off → 기존 예약 알림 취소(D-07 (a)), 이후 저장·수정 일정은 알림 미예약.
   - on → 이후 저장·수정 일정부터 개별 설정대로 재예약. (권한 거부 상태면 안내·설정 이동 유도 E-18-1)
3. "새 일정 기본 중요도" 선택(높음/보통/낮음) — 이후 일정 작성 화면 초기값에 반영.
4. "새 일정 기본 유형" 선택(유형 목록) — 이후 일정 작성 화면 초기값에 반영. 해당 유형 삭제 시 "기타"로 자동 복귀.
5. 변경은 즉시 저장·재실행 후 유지.

### 7.10 애플워치에서 오늘 일정 확인·완료 (F-19)

1. 사용자가 애플워치에서 "오늘뭐해" 워치 앱을 연다(또는 D-10 결정 시 컴플리케이션 탭).
2. 워치가 폰과 연결되어 있으면 최신 "오늘 + 다음 예정 1건" 스냅샷을 받아 목록을 표시한다. 연결 불가면 마지막 스냅샷을 "최신 아님" 표시와 함께 보여준다(E-19-1).
3. 사용자가 목록을 훑고, 필요한 항목의 완료 컨트롤을 탭해 완료/미완료를 토글한다.
4. 워치 화면의 완료/미완료 카운트가 즉시 갱신된다.
5. 역전파 분기:
   - 5-a 폰 연결됨 → 변경이 폰으로 전송되어 폰 대시보드 집계에 반영된다(AC-23 / AC-48).
   - 5-b 폰 연결 안 됨 → 변경을 워치 보류 큐에 저장, 연결 복구 시 전송하고 충돌은 P-38(마지막 쓰기 우선)로 해소한다(AC-49 / AC-50).
6. 사용자가 생성·편집 등 워치 비범위 동작을 시도하면 해당 진입점이 없거나 "폰에서 계속" 안내로만 연결된다(P-43, AC-51).
7. 폰에서 일정이 바뀌면 워치는 다음 갱신 시점(P-37)에 목록을 갱신한다.

### 7.11 대시보드 날짜 네비게이션 · 진행률 한 줄 · 접이식 날짜별 검색 (F-20 / F-21 / F-22, v1.6 재확정 방향)

1. 사용자가 "오늘" 탭(대시보드)에 진입한다. 기준 날짜 = 오늘. 위→아래로 **브랜드 영역 → 날짜 네비게이션 영역(작게, "오늘 · 9월 9일 (수)" + 좌/우 화살표) → 진행률 한 줄("M / N 완료" + progress bar) → 접이식 검색 아이콘(접힌 상태) → 요약 상세(완료율·유형별 분포·다음 예정) → 오늘 일정 리스트 → FAB**가 표시된다.
2. 좌 화살표를 탭한다 → 기준 날짜가 어제로 이동한다. 진행률 한 줄·요약·리스트가 어제 기준으로 갱신되고 "오늘로" 복귀 컨트롤이 나타난다.
3. 우 화살표를 탭한다 → 기준 날짜가 하루 뒤로 이동한다(연속 탭 시 누적, E-20-4). **기준 날짜가 미래이면 진행률 한 줄은 progress bar 없이 "일정 N건"만 표시한다(P-52).**
4. "오늘로" 복귀 컨트롤을 탭한다 → 기준 날짜가 오늘로 즉시 복귀하고 복귀 컨트롤이 숨겨진다. 펼쳐져 있던 접이식 검색은 접히고 검색어가 있으면 초기화된다(P-50, P-53).
5. 검색 아이콘을 탭한다 → 검색 입력창이 펼쳐지고 포커스가 이동한다. "회의"를 입력한다 → 리스트가 기준 날짜 일정 중 제목·메모에 "회의"가 포함된 항목만 실시간 표시한다. 진행률 한 줄 수치·progress bar는 그대로다(P-49).
6. 검색 결과가 0건이면 → 리스트 영역에 "검색어에 해당하는 오늘 일정이 없습니다" 안내와 지우기 유도가 표시된다(E-22-1). "그 날짜에 일정 없음"(E-10-1)과는 문구로 구분된다.
7. 검색어를 유지한 채 좌/우 화살표로 날짜를 이동한다 → 새 기준 날짜 목록에 같은 검색어가 재적용된다(E-22-2). 지우기 컨트롤을 탭하거나 입력을 지우면 전체 목록이 복원된다(E-22-4). 검색 아이콘을 다시 탭하면 입력창이 접히고, 접힘 시 검색어는 초기화된다(D-18 가정, E-22-6).
8. 다른 날짜를 보는 중 자정이 지나고 화면을 갱신한다 → 원래 "오늘"을 보고 있었다면 새 오늘로 이동하고, 다른 날짜였다면 그 날짜를 유지한다(P-46). "오늘로" 복귀 시 새 오늘로 간다.

## 9. Acceptance Criteria (검증 가능 형태)

표기: Given / When / Then

### AC-01 일정 등록

- Given 제목·시작일시·유형·우선순위를 입력했고
- When 저장을 누르면
- Then 일정이 목록·대시보드·캘린더 뷰에 나타나고, 앱 재실행 후에도 유지된다.

### AC-02 필수값 검증

- Given 제목이 비었거나 시작일시가 없을 때
- When 저장을 누르면
- Then 저장되지 않고 어떤 필드가 문제인지 안내가 표시된다.

### AC-03 종료<시작 검증

- Given 종료일시가 시작일시보다 이르면
- When 저장을 누르면
- Then 저장이 거부된다.

### AC-04 완료 토글과 집계

- Given 금일 일정 4건 중 1건이 완료 상태일 때
- When 미완료 1건을 완료로 토글하면
- Then 대시보드 완료 수가 2, 완료율이 50%로 갱신된다.

### AC-05 사전 알림 발송

- Given 30분 뒤 시작 일정에 "10분 전" 사전 알림을 설정했을 때
- When 시작 20분 전 시각이 되면
- Then 해당 일정의 로컬 알림이 1회 발송된다(제목/시각 포함, P-10-1 설정에 따라 제목 마스킹).

### AC-06 정시 알림 발송

- Given 정시 알림이 켜진 일정이 있을 때
- When 시작 시각이 되면
- Then "지금 시작" 알림이 1회 발송된다.

### AC-07 알림 권한 거부

- Given 사용자가 알림 권한을 거부한 상태에서
- When 사전/정시 알림이 있는 일정을 저장하면
- Then 일정은 저장되고, 알림이 동작하지 않음을 알리는 안내와 설정 이동 경로가 제공된다.

### AC-08 재부팅 후 알림 복원

- Given 미래 알림이 예약된 일정이 있고 기기를 재부팅했을 때
- When 부팅이 완료되면
- Then 해당 알림 예약이 복원되어 예정 시각에 발송된다.

### AC-09 수정 시 알림 재예약

- Given 알림이 예약된 일정의 시작 시각을 변경하고 저장하면
- When 저장이 완료되면
- Then 이전 예약은 취소되고 새 시각 기준으로 알림이 재예약된다.

### AC-10 삭제 시 알림 제거

- Given 알림이 예약된 일정을 삭제하면
- Then 일정과 그 일정의 모든 알림 예약이 제거된다.

### AC-11 유형별 필터

- Given "업무" 유형 일정 3건, "취미" 2건이 있을 때
- When 목록에서 "업무" 필터를 적용하면
- Then 업무 3건만 표시된다.

### AC-12 우선순위 정렬

- Given 우선순위가 섞인 일정 목록에서
- When "우선순위순" 정렬을 선택하면
- Then 높음 → 보통 → 낮음 순으로 정렬된다.

### AC-13 검색

- Given 제목에 "회의"가 포함된 일정 2건, 메모에 "회의"가 포함된 1건이 있을 때
- When "회의"로 검색하면
- Then 3건이 결과에 표시된다.

### AC-14 검색 + 필터

- Given AC-13 상태에서
- When "회의" 검색에 "완료=미완료" 필터를 더하면
- Then 미완료인 회의 일정만 표시된다.

### AC-15 대시보드 빈 상태 (v1.3 정정)

- Given 금일 일정이 0건이면
- When 대시보드를 열면
- Then 상단 로고·태그라인과 요약(총계 0 / 완료 0 / 완료율 0%)이 표시되고, 목록 영역에 "오늘 일정이 없습니다" 안내와 명시적 "일정 추가" 버튼이 표시되며, 화면에는 상시 FAB(플로팅 추가 버튼)도 함께 표시된다.
- 확정: 빈 상태의 "일정 추가" 버튼과 상시 FAB를 **둘 다** 둔다(재설계 구현이 도입한 FAB 존치 + 빈 상태에서의 명시적 추가 유도 유지).

### AC-16 자정 경과

- Given 대시보드를 열어 둔 상태에서 자정이 지나면
- When 화면을 갱신하면
- Then 기준 날짜가 다음 날로 바뀌고 그 날짜의 집계가 표시된다.

### AC-17 테마 지정 유지

- Given 다크 테마와 강조색을 선택하면
- When 앱을 재실행하면
- Then 선택한 테마·강조색이 그대로 적용되어 있다.

### AC-18 캘린더 읽기 연동

- Given 캘린더 접근 권한을 허용하고 캘린더 1개를 선택하면
- When 앱의 캘린더 뷰를 열면
- Then 해당 캘린더의 일정이 앱 일정과 함께 병합 표시된다.

### AC-19 캘린더 중복 병합

- Given 앱 일정과 외부 캘린더 일정이 P-08 기준으로 동일하다고 판정되면
- When 캘린더 뷰를 보면
- Then 중복 없이 1건으로 표시되고 사용자가 편집한 로컬 필드가 보존된다.

### AC-20 계정 없이 사용

- Given 로그인하지 않은 상태에서
- When F-01~F-11, F-13, F-15, F-18 및 F-06 유형 관리 기능을 사용하면
- Then 모두 정상 동작한다(계정 요구로 막히지 않는다).

### AC-21 계정 연동/해제

- Given 계정을 연동한 뒤 설정에서 연동을 해제하면
- Then 연동 상태 표시가 사라지고 로컬 일정 데이터는 그대로 유지된다.

### AC-22 오프라인 동작

- Given 네트워크가 없는 상태에서
- When 일정 등록·수정·삭제·완료·검색을 하면
- Then 모두 정상 동작하고, 네트워크 복구 시 (D-01=(a)인 경우) 동기화가 재개된다.

### AC-23 워치 완료 체크 반영

- Given 모바일과 페어링된 워치에서 금일 일정을 완료로 토글하면
- When 모바일 대시보드를 보면
- Then 완료 상태와 집계가 동일하게 반영된다.

### AC-25 대시보드 로고 표시

- Given 앱이 실행되어 대시보드 화면이 열리면
- When 화면이 렌더링될 때
- Then 로고(logo.png)가 화면 상단에 표시되고, 태그라인(tagline.png)이 로고 하단에 표시된다

### AC-26 탭 아이콘 표시

- Given 앱의 하단 탭 내비게이터가 표시되면
- When 사용자가 탭 바를 보면
- Then 오늘 탭에 todo.png, 캘린더 탭에 goal.png, 검색 탭에 statistics.png, 설정 탭에 settings.png 아이콘이 라벨과 함께 표시된다

### AC-27 탭 아이콘 활성 상태 구분

- Given 탭 내비게이터가 표시된 상태에서
- When 특정 탭이 활성화되어 있으면
- Then 해당 탭의 아이콘이 강조색으로 표시되고, 비활성 탭은 회색조로 표시된다

### AC-28 에셋 로드 실패 시 앱 정상 동작

- Given 에셋 파일이 로드되지 않는 상황에서(예: 잘못된 경로)
- When 해당 화면이 표시되면
- Then 앱이 크래시되지 않으며 나머지 기능은 정상 동작한다

### AC-24 데이터 마이그레이션

- Given 이전 스키마로 저장된 데이터가 있는 상태에서 앱을 업데이트하면
- When 앱을 실행하면
- Then 마이그레이션이 수행되어 기존 일정이 유실 없이 표시된다.

### AC-29 브랜드 로딩 인디케이터 표시

- Given 로딩이 표시 지연 임계 시간을 초과해 지속되면
- When 해당 로딩 화면/영역을 보면
- Then OS 표준 스피너가 아닌 오리 캐릭터 애니메이션이 표시된다.

### AC-30 오리 활동 순환

- Given 오리 로딩 애니메이션이 표시된 상태에서
- When 애니메이션을 계속 지켜보면
- Then 오리가 3~5개의 도메인 활동(일정 확인·달력 넘기기·알림 종 울리기·완료 체크 등)을 정해진 순서로 반복해서 보여준다.

### AC-31 최소 표시 시간 (깜빡임 방지)

- Given 오리 인디케이터가 표시된 직후
- When 최소 표시 시간이 지나기 전에 로딩이 끝나면
- Then 인디케이터는 최소 표시 시간까지 유지된 뒤 사라진다.

### AC-32 빠른 로딩 시 미표시

- Given 로딩이 표시 지연 임계 시간 이내에 완료되면
- When 화면이 갱신될 때
- Then 오리 인디케이터가 한 번도 나타나지 않는다.

### AC-33 동작 줄이기 정적 폴백

- Given OS "동작 줄이기(Reduce Motion)" 설정이 켜진 상태에서
- When 로딩 상태에 진입하면
- Then 애니메이션 대신 정지된 오리 이미지와 "불러오는 중…" 텍스트가 표시된다.

### AC-34 렌더 실패 시 폴백 및 무크래시

- Given 오리 SVG/애니메이션을 렌더링할 수 없는 상황에서
- When 로딩 상태에 진입하면
- Then 정적 폴백 이미지(또는 그것도 실패 시 OS 표준 스피너)가 표시되고 앱은 크래시하지 않는다.

### AC-35 로딩 종료 시 콘텐츠 표시

- Given 오리 인디케이터가 표시된 상태에서 로딩이 성공적으로 끝나면
- When 최소 표시 시간 조건을 만족하면
- Then 인디케이터가 사라지고 실제 콘텐츠(요약/캘린더/검색 결과 등)가 표시된다.

### AC-36 노출 위치 구분

- Given 앱 부트스트랩 초기 데이터 로드와 대시보드/캘린더/검색의 부분 로딩이 각각 발생하면
- When 각 로딩이 인디케이터를 표시하면
- Then 부트스트랩은 풀스크린 중앙에, 나머지는 해당 콘텐츠 영역 인라인(소형)으로 표시된다.

### AC-37 접근성 라벨

- Given 스크린리더가 켜진 상태에서 오리 인디케이터가 표시되면
- When 인디케이터에 포커스가 가면
- Then "불러오는 중" 의미의 라벨이 읽히고, 활동이 바뀔 때마다 반복해서 읽지 않는다.

### AC-38 에러 종료 시 인디케이터 제거

- Given 오리 인디케이터가 표시된 상태에서 로딩이 실패로 끝나면
- When 상태가 에러로 전환되면
- Then 인디케이터가 즉시 사라지고 재시도 경로가 있는 에러 UI가 표시된다.

### AC-39 유형 이름변경 즉시 반영 (v1.3)

- Given "업무" 유형을 사용하는 일정 3건이 목록·대시보드·검색에 표시되고 있을 때
- When 유형 관리 화면에서 "업무"의 이름을 "회사"로 변경하면
- Then 별도 새로고침 없이 그 3건의 유형 라벨이 모두 "회사"로 바뀌고, 유형 선택 UI에도 "회사"로 표시되며, 일정-유형 연결(참조)은 유지된다.

### AC-40 기본 유형 보호 (v1.3)

- Given 유형 관리 화면에서 기본 유형 "기타"를 선택했을 때
- When 삭제 또는 이름변경을 시도하면
- Then 해당 조작이 제공되지 않거나(비활성) 거부되고, "기본 유형은 변경할 수 없습니다" 취지의 안내가 표시된다.

### AC-41 유형 이름 검증 (v1.3)

- Given 유형 목록에 "공부"가 이미 있을 때
- When 새 유형 이름을 빈 값/공백으로, 또는 "공부"(앞뒤 공백·대소문자만 다른 값 포함)로 추가하거나 다른 유형의 이름을 그렇게 변경하려 하면
- Then 저장되지 않고 사유(빈 이름 / 중복 이름)를 알리는 안내가 표시된다.

### AC-42 전역 알림 사용 off (v1.3)

- Given 알림이 예약된 일정이 있고 전역 "알림 사용"이 on일 때
- When 설정에서 "알림 사용"을 off로 바꾸면
- Then 기존에 예약된 사전/정시 알림이 취소되고, 이후 저장·수정하는 일정에도 알림이 예약되지 않는다.
- And When 다시 on으로 바꾸고 어떤 일정을 저장·수정하면 그 일정의 알림 설정대로 알림이 다시 예약된다.

### AC-43 새 일정 기본값 적용 (v1.3)

- Given 설정에서 새 일정 기본 중요도를 "높음", 기본 유형을 "업무"로 지정했을 때
- When 일정 작성 화면을 새로 열면
- Then 중요도 필드가 "높음", 유형 필드가 "업무"로 미리 선택되어 있고, 사용자가 저장 전에 다른 값으로 바꿀 수 있다.
- And 기본값을 지정하지 않았다면 중요도는 "보통", 유형은 "기타"로 미리 선택된다.

### AC-44 대시보드 인라인 완료 토글 (v1.3)

- Given 대시보드 "오늘 일정 목록"에 미완료 3건, 완료 1건이 있을 때
- When 목록에서 미완료 1건의 완료 체크를 탭하면
- Then 그 항목이 즉시 완료로 표시되고, 요약의 완료 수가 2, 완료율이 50%로 갱신되며, 앱 재실행 후에도 유지된다.

### AC-45 대시보드 스와이프 삭제 (v1.3)

- Given 대시보드 "오늘 일정 목록"에 알림이 예약된 일정이 있을 때
- When 그 항목을 스와이프하여 삭제하고 삭제 확인을 승인하면
- Then 일정과 그 일정의 모든 알림 예약이 제거되고, 목록과 요약(총계·완료율·유형별 분포)에서 사라진다.
- And 삭제 확인을 취소하면 항목은 그대로 남는다.

### AC-46 대시보드 브랜드·요약 공존 (v1.3, AC-25 회귀 방지 강화)

- Given 대시보드에 상호작용형 "오늘 일정 목록"이 표시되는 상태에서
- When 대시보드를 열면
- Then 상단에 로고(logo.png)와 태그라인(tagline.png)이 표시되고, 완료율(%)·유형별 분포·다음 예정 일정 요약이 목록과 같은 화면에 함께 표시된다.

### AC-47 워치 오늘 목록 표시 (v1.4)

- Given 아이폰 앱에 오늘 일정 3건(1건 완료)이 있고 워치가 폰과 연결된 상태에서
- When 애플워치 워치 앱을 열면
- Then 오늘 일정 3건이 시작 시각순으로, 각 항목에 제목·시작 시각·유형·완료 상태가 표시되고, 목록 헤더에 완료 1 / 미완료 2가 표시된다.

### AC-48 워치 완료 토글 역전파 (v1.4, AC-23 확장)

- Given 워치와 폰이 연결된 상태에서 워치 오늘 목록에 미완료 일정이 있을 때
- When 워치에서 그 일정의 완료 컨트롤을 탭하면
- Then 워치 화면의 완료/미완료 카운트가 즉시 갱신되고, 폰 대시보드를 열면 동일 일정이 완료로, 완료 수·완료율이 동일하게 반영되어 있다.

### AC-49 워치 오프라인 조회·보류 큐 (v1.4)

- Given 워치가 폰과 연결되지 않은 상태에서
- When 워치 앱을 열고 어떤 일정의 완료를 토글하면
- Then 마지막으로 받은 "오늘" 스냅샷이 "최신 아님" 표시와 함께 조회되고, 완료 변경은 보류로 저장되었다가 폰 연결이 복구되면 폰으로 전송되어 반영된다.

### AC-50 워치 오프라인 충돌 해소 (v1.4)

- Given 같은 일정을 워치(오프라인, 보류)와 폰에서 각각 다른 완료 상태로 변경했을 때
- When 워치가 폰에 다시 연결되어 동기화되면
- Then 더 나중 타임스탬프의 변경이 최종 완료 상태로 남는다(마지막 쓰기 우선, P-38).

### AC-51 워치 비범위 동작 차단 (v1.4)

- Given 워치 앱을 사용하는 중에
- When 일정 생성·편집·삭제·스누즈·검색·유형 관리·설정 변경을 시도하면
- Then 워치에는 해당 기능 진입점이 없거나 "폰에서 계속" 안내만 제공되고, 워치에서 그 조작이 실행되지 않는다.

### AC-52 워치 알림 예약 주체 (v1.4)

- Given 사전/정시 알림이 설정된 일정이 있고 전역 "알림 사용"이 on일 때
- When 알림 시각이 되면
- Then 알림은 폰이 예약·발송한 것이며(워치가 독립 예약하지 않음), 페어링된 워치에는 iOS 기본 미러링으로 노출된다.
- And 전역 "알림 사용"이 off이면 워치에도 알림이 노출되지 않는다.

### AC-53 워치 페이로드 범위 (v1.4)

- Given 폰 앱에 과거·미래를 포함해 다수의 일정이 있을 때
- When 워치가 폰으로부터 동기화를 받으면
- Then 워치에는 오늘 일정과 다음 예정 1건만 내려오고, 과거 전체 이력이나 검색 데이터는 워치로 전송되지 않는다.

### AC-54 워치 빈 상태 (v1.4)

- Given 오늘 일정이 0건일 때
- When 워치 앱을 열면
- Then "오늘 일정이 없습니다" 안내가 표시되고, 일정 추가 버튼은 제공되지 않는다(생성은 폰 전용).

### AC-55 Wear OS 이번 범위 제외 (v1.4)

- Given 이번 릴리스 범위에서 워치 기능을 검증할 때
- When 산출물과 검증 대상을 확인하면
- Then 애플워치(watchOS) 워치 앱만 대상이며, Android Wear OS 워치 앱은 산출물·검증 대상에 포함되지 않는다(후속, OI-11).

### AC-56 워치 컴플리케이션 (D-10 결정 시, v1.4)

- Given D-10이 "포함"으로 확정된 경우
- When 워치 페이스에 컴플리케이션을 추가하면
- Then "오늘 남은(미완료) 일정 수"가 표시되고, 탭하면 워치 앱이 실행된다.
- 참고: D-10이 "후속"으로 확정되면 본 AC는 이번 릴리스 검증 대상에서 제외된다(OI-12).

### AC-57 대시보드 날짜 앞뒤 이동 (v1.5)

- Given 대시보드 기준 날짜가 오늘이고 오늘 일정 2건, 어제 일정 3건이 있을 때
- When 좌 화살표를 한 번 탭하면
- Then 날짜 표시가 어제로 바뀌고, 개수 카드·요약·목록이 어제 일정 3건 기준으로 갱신되며, "오늘로" 복귀 컨트롤이 나타난다.

### AC-58 오늘로 복귀 (v1.5)

- Given 기준 날짜를 좌/우 화살표로 오늘이 아닌 날짜로 옮긴 상태에서
- When "오늘로" 복귀 컨트롤을 탭하면
- Then 기준 날짜가 오늘로 즉시 돌아오고, "오늘로" 복귀 컨트롤이 사라지며, 입력돼 있던 인라인 검색어가 있으면 초기화된다.

### AC-59 다른 날짜 조회 중 자정 경과 (v1.5)

- Given 대시보드에서 기준 날짜를 "오늘이 아닌 날짜"로 옮겨 둔 채 자정이 지났을 때
- When 화면을 갱신하면
- Then 그 기준 날짜(달력상 날짜)는 유지되고, "오늘로" 복귀 컨트롤은 새로운 오늘을 가리킨다.
- And 자정 직전 "오늘"을 보고 있었던 경우에는 기준 날짜가 새 오늘로 함께 이동한다(E-10-2 / P-46).

### AC-60 진행률 한 줄 표시와 실시간 갱신 (v1.5 / v1.6 재정의)

- Given 기준 날짜(오늘 또는 과거)에 일정 4건 중 1건이 완료 상태일 때
- When 대시보드를 열면
- Then 진행률 한 줄에 "1 / 4 완료" 텍스트와 25% 채워진 progress bar 1개가 표시된다.
- And When 미완료 1건을 완료로 토글하면 진행률 한 줄이 "2 / 4 완료" + 50% progress bar로 즉시 갱신되고 요약 상세의 완료율이 50%가 된다.

### AC-61 진행률 한 줄 빈 상태 (v1.5 / v1.6 재정의)

- Given 기준 날짜(오늘 또는 과거)에 일정이 0건일 때
- When 대시보드를 열면
- Then 진행률 한 줄이 "0 / 0 완료" + 0%(빈) progress bar로 표시되고, 목록 영역에는 E-10-1 빈 상태 안내가 표시된다.

### AC-62 접이식 검색 펼침 후 실시간 필터링 (v1.5 / v1.6 재정의)

- Given 기준 날짜 일정 목록에 제목에 "회의"가 있는 2건, 메모에 "회의"가 있는 1건, 무관한 3건이 있고 검색창은 접혀 있을 때
- When 검색 아이콘을 탭해 입력창을 펼치고 "회의"를 입력하면
- Then 리스트에 그 3건만 실시간으로 남고, 진행률 한 줄 수치("3 / 6 완료" 등)와 progress bar는 변하지 않는다.

### AC-63 접이식 검색 결과 없음 (v1.5 / v1.6 문구 정정)

- Given 기준 날짜에 일정은 있으나 검색어와 일치하는 항목이 없을 때
- When 검색창을 펼치고 검색어를 입력하면
- Then 리스트 영역에 "검색어에 해당하는 오늘 일정이 없습니다" 취지의 빈 결과 안내와 검색어 지우기 유도가 표시되고, 이는 "그 날짜에 일정이 없음"(AC-61 / E-10-1) 안내와 문구로 구분된다.

### AC-64 접이식 검색어 초기화 (v1.5 / v1.6 재정의)

- Given 검색창이 펼쳐지고 검색어가 입력되어 목록이 필터된 상태에서
- When 입력창의 지우기 컨트롤을 탭하거나 검색어를 모두 지우면
- Then 검색이 해제되고 기준 날짜의 전체 목록이 복원된다(입력창은 펼친 상태 유지).
- And 검색 아이콘을 다시 탭해 입력창을 접으면, D-18 가정에 따라 검색어가 초기화되고 전체 목록이 유지된다(E-22-6).

### AC-65 날짜 이동 시 검색어 유지·재적용 (v1.5 / v1.6 재정의)

- Given 검색창이 펼쳐지고 검색어 "운동"이 입력된 상태에서
- When 우 화살표로 다음날로 이동하면
- Then 검색어 "운동"이 유지된 채 다음날 일정 목록에 재적용되어 필터된 결과가 표시된다.
- And "오늘로" 복귀하거나 대시보드 탭을 벗어났다 다시 들어오면 검색어는 초기화되고 검색창은 접힌다(P-50, P-53).

### AC-66 접이식 검색과 전역 검색 독립 (v1.5 / v1.6 문구 정정)

- Given 대시보드 접이식 검색창에 "회의"를 입력한 상태에서
- When 검색 탭(F-11)으로 이동하면
- Then 전역 검색 입력은 비어 있고(대시보드 검색어가 전파되지 않음), 대시보드로 돌아왔을 때 검색창/검색어 상태는 P-50·P-53 규칙에 따라 결정된다.

### AC-67 접이식 검색 토글 (v1.6 신규)

- Given 대시보드에 진입했을 때 진행률 한 줄과 리스트 사이에 검색 아이콘만 보이고 입력창은 접혀 있을 때
- When 검색 아이콘을 탭하면
- Then 검색 입력창이 펼쳐지고 입력 포커스가 이동한다.
- And When 검색 아이콘(또는 접기 컨트롤)을 다시 탭하면 입력창이 접히고, D-18 가정에 따라 검색어가 초기화되어 기준 날짜 전체 목록이 표시된다.

### AC-68 미래 날짜 진행률 한 줄 표시 (v1.6 신규)

- Given 기준 날짜를 우 화살표로 내일(미래)로 옮겼고 그 날 일정이 5건일 때
- When 대시보드를 보면
- Then 진행률 한 줄은 "일정 5건" 취지로 총 개수만 표시하고, progress bar와 완료율·완료 수는 표시하지 않는다(P-52).
- And 기준 날짜를 오늘 또는 과거로 되돌리면 "M / N 완료" 텍스트 + progress bar 표시가 복원된다.
