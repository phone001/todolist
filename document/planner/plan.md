## 1. 목적 (Why)

- 개인이 하루/주/월 단위 일정을 **등록·분류·완료 관리**하고, 일정 시각 전에 **알림**을 받아 할 일을 놓치지 않도록 돕는다.
- "오늘 해야 할 일"을 한 화면(대시보드)에서 완료/미완료로 파악하게 한다.
- 기기의 **기본 캘린더**와 연동하여 기존 일정 흐름을 깨지 않는다.

### 성공 판단 기준 (제품 관점, 정성)

- 사용자가 일정 등록부터 알림 수신, 완료 체크까지 앱을 벗어나지 않고 수행할 수 있다.
- 알림이 설정한 시각/사전 간격에 실제로 도달한다.
- 앱을 재실행해도 등록한 일정과 설정이 그대로 유지된다.

---

## 2. 사용자 식별 (Who)

| 사용자 | 설명 | 주 사용 시나리오 |
| --- | --- | --- |
| 개인 사용자 (기본) | 앱을 설치한 단말의 소유자. 로그인 없이도 사용 가능 | 일정 등록, 알림 수신, 완료 체크, 검색 |
| 계정 연동 사용자 | 외부 계정(예: Google 등)을 연동한 개인 사용자 | 여러 기기 간 일정 동기화, 기본 캘린더 연동 |
| 스마트워치 사용자 | 모바일 앱과 페어링된 워치 착용자 | 알림 확인, 금일 일정 조회, 완료 체크 |

- 다중 사용자(팀/공유 일정), 관리자, 게스트 개념은 이번 범위에 **없음(확정)**.

---

## 3. 범위 (Scope)

### 3.1 이번 릴리스 포함 (확정)

1. 일정 관리 (CRUD, 완료 체크, 유형, 우선순위)
2. 알림 (사전 알림 + 정시 알림)
3. 대시보드 (금일 완료/미완료 집계)
4. 일정 검색
5. 계정 연동
6. 스타일(테마) 지정
7. 기본 캘린더 연동

### 3.2 이번 릴리스 제외 (확정)

- 팀/공유 일정, 일정 위임, 초대
- 반복 일정의 복잡한 예외 규칙(RFC 5545 전체) — 아래 5.1의 제한된 반복만 포함
- 위치 기반 알림, 음성 입력
- 웹/데스크톱 클라이언트

### 3.3 가정 (Assumption — Architect/이해관계자 확인 필요)

- **A-1**: "계정 연동"은 (a) 외부 OAuth 로그인 + 자체 동기화 서버 도입, (b) 단말 OS 계정(Google/Apple)에 붙어 캘린더 API만 사용, (c) 로그인만 하고 동기화는 캘린더 연동에 위임 중 하나다. 본 기획은 **(c)를 기본 가정**으로 하며 최종 결정은 이해관계자(정책 게이트 D-01)에 위임한다.
- **A-2**: 스마트워치 앱은 모바일 앱의 **보조 클라이언트**이며 독립 저장소를 갖지 않는다(모바일과 동기화된 데이터를 표시).
- **A-3**: 오프라인이 기본 동작 환경이다. 네트워크는 계정 연동/캘린더 동기화 시에만 필요하다.
- **A-4**: 개인정보(일정 제목/메모)는 단말 로컬(SQLite)에 저장된다. 서버 저장 여부는 D-01에 종속.

## 4. 기능 요구사항 (What / Action / Result / Exception)

표기: **확정** = 원본 요구사항에서 직접 도출 / **가정** = Planner가 보완(검증 필요)

### F-01 일정 등록 (확정)

- Who: 개인 사용자
- When: 앱 실행 중 언제든
- What: 새 일정을 생성한다
- Action: 제목, 시작 일시, (선택) 종료 일시, 유형, 우선순위, (선택) 메모, 알림 설정을 입력하고 저장한다
- Result: 일정이 저장되고 목록/대시보드/캘린더 뷰에 즉시 반영된다. 알림 설정이 있으면 알림이 예약된다
- Exception:
  - E-01-1 제목이 비어 있음 → 저장 불가, 안내 메시지
  - E-01-2 시작 일시 미선택 → 저장 불가
  - E-01-3 종료 일시가 시작보다 빠름 → 저장 불가
  - E-01-4 과거 시각으로 사전 알림 설정 → 알림은 예약하지 않고 일정만 저장, 경고 표시

### F-02 일정 조회 (확정)

- Who: 개인 사용자 / 워치 사용자
- What: 등록된 일정을 목록·일간·주간·월간으로 본다
- Action: 날짜 이동, 뷰 전환, 일정 선택 시 상세 표시
- Result: 선택 기간의 일정이 시간순으로 표시된다. 완료 항목은 시각적으로 구분된다
- Exception:
  - E-02-1 해당 기간에 일정 없음 → 빈 상태 안내
  - E-02-2 데이터 로드 실패 → 재시도 안내, 마지막 캐시 표시

### F-03 일정 수정 (확정)

- Action: 기존 일정의 필드를 변경하고 저장
- Result: 변경 내용 저장, 알림 설정이 바뀌면 기존 예약 취소 후 재예약
- Exception: F-01의 검증 규칙 동일 적용. 이미 완료된 일정도 수정 가능(정책 P-05)

### F-04 일정 삭제 (확정)

- Action: 일정을 삭제한다
- Result: 일정 및 연결된 알림 예약이 제거된다. 삭제 확인 절차를 거친다
- Exception:
  - E-04-1 캘린더 연동으로 생성된 일정 삭제 → 정책 P-08에 따름
  - E-04-2 삭제 취소(Undo)는 저장 직후 일정 시간 내 제공(가정)

### F-05 완료 체크 (확정)

- Who: 개인 사용자 / 워치 사용자
- Action: 일정의 체크박스를 토글한다
- Result: 완료/미완료 상태가 즉시 저장되고 대시보드 집계에 반영된다. 완료 시각을 기록한다
- Exception:
  - E-05-1 미래 일정도 완료 체크 가능(정책 P-06)
  - E-05-2 저장 실패 → 상태 롤백, 재시도 안내

### F-06 유형(카테고리) 지정 (확정)

- What: 일정을 유형으로 분류한다 (예: 취미, 공부, 업무)
- Action: 일정 작성/수정 시 유형 선택. 사용자 정의 유형 추가/이름변경/삭제 가능(가정)
- Result: 유형별 색상/아이콘으로 구분 표시, 유형별 필터·검색 가능
- Exception:
  - E-06-1 유형 미선택 → 기본 유형("기타")으로 저장
  - E-06-2 사용 중인 유형 삭제 → 해당 일정은 "기타"로 이동, 삭제 확인

### F-07 우선순위 지정 (확정)

- What: 일정에 우선순위를 부여한다
- Action: 높음/보통/낮음 3단계 중 선택(가정: 단계 수)
- Result: 목록에서 우선순위 표식 표시, 우선순위로 정렬·필터 가능
- Exception: E-07-1 미선택 → "보통"으로 저장

### F-08 사전 알림 (확정)

- Who: 개인 사용자
- When: 일정 시작 시각 기준 사전 오프셋(예: 1일 전, N분 전) 도달 시
- What: 일정 시작 전에 미리 알림을 보낸다
- Action: 일정별로 사전 알림 오프셋을 0개 이상 설정 (프리셋: 5/10/30분, 1시간, 1일 + 사용자 지정)
- Result: 각 오프셋 시각에 로컬 알림(제목/시각/유형 표시)이 발송된다. 워치에도 전달된다
- Exception:
  - E-08-1 알림 권한 거부 → 앱 내 안내, 설정 이동 유도, 일정은 정상 저장
  - E-08-2 오프셋 시각이 이미 과거 → 해당 오프셋은 건너뜀
  - E-08-3 기기 재부팅/앱 강제종료 후 → 예약이 복원되어야 함(정책 P-09)
  - E-08-4 방해 금지 시간대 → OS 정책에 따름, 앱은 별도 우회하지 않음

### F-09 정시 알림 (확정)

- When: 일정 시작 시각 도달 시
- Result: "지금 시작" 알림 발송
- Exception: F-08의 예외 규칙을 동일 적용

### F-10 대시보드 (확정)

- Who: 개인 사용자 / 워치 사용자
- What: 금일(및 선택 날짜) 일정의 완료/미완료 현황을 요약한다
- Action: 앱 첫 화면에서 확인. 항목 탭 시 해당 일정으로 이동
- Result: 총계, 완료 수, 미완료 수, 완료율(%), 유형별 분포, 다음 예정 일정을 표시
- Exception:
  - E-10-1 금일 일정 0건 → "오늘 일정이 없습니다" + 일정 추가 유도
  - E-10-2 자정 경과 → 기준 날짜가 자동으로 갱신된다

### F-11 일정 검색 (확정)

- What: 제목/메모/유형으로 일정을 찾는다
- Action: 검색어 입력, (선택) 기간·유형·완료여부·우선순위 필터 적용
- Result: 일치 일정을 관련도/날짜순으로 표시, 결과에서 바로 상세 이동
- Exception:
  - E-11-1 검색어 0건 → 빈 결과 안내
  - E-11-2 검색어 1글자 → 허용하되 결과가 많을 수 있음을 안내(가정: 최소 글자수 정책 P-11)

### F-12 계정 연동 (확정, 세부는 가정)

- Who: 계정 연동을 원하는 개인 사용자
- What: 외부 계정을 연동/해제한다
- Action: 계정 로그인(OAuth) → 권한 동의 → 연동 완료. 설정에서 연동 해제 가능
- Result: 연동 상태 표시. (D-01 결정에 따라) 기기 간 동기화 또는 캘린더 접근이 활성화된다
- Exception:
  - E-12-1 로그인 취소/실패 → 로컬 전용 모드 유지
  - E-12-2 토큰 만료 → 재인증 요청, 만료 동안 로컬 동작 유지
  - E-12-3 연동 해제 → 로컬 데이터는 유지, 서버/캘린더 동기화만 중단(가정)

### F-13 스타일(테마) 지정 (확정)

- What: 앱 외형을 사용자가 바꾼다
- Action: 라이트/다크/시스템 테마 선택, 강조 색상 선택, (가정) 글자 크기 조절
- Result: 설정 즉시 앱 전체에 적용되고 재실행 후에도 유지된다
- Exception: E-13-1 시스템 테마 변경 시 "시스템" 선택이면 자동 반영

### F-14 기본 캘린더 연동 (확정)

- What: 단말의 기본 캘린더(iOS EventKit / Android Calendar Provider)와 일정을 주고받는다
- Action: 캘린더 접근 권한 동의 → 가져올 캘린더 선택 → 양방향/단방향 동기화 범위 설정(가정)
- Result:
  - 외부 캘린더 일정이 앱에 표시된다(읽기)
  - 앱에서 만든 일정을 선택한 캘린더에 반영한다(쓰기, 가정: 옵션)
- Exception:
  - E-14-1 권한 거부 → 캘린더 연동 비활성, 앱 자체 일정은 정상
  - E-14-2 동일 일정 중복(앱↔캘린더) → 중복 판정 규칙 P-08로 병합/표시
  - E-14-3 충돌(양쪽 동시 수정) → "기기 캘린더 우선" 기본, 사용자 선택 옵션(가정)
  - E-14-4 대량 일정 → 동기화는 백그라운드로 처리, 진행 표시

### F-15 로컬 데이터 영속화 (가정 — 원본의 "데이터베이스: SQLite"에서 도출)

- What: 모든 일정/유형/설정/알림 예약을 단말에 저장한다
- Result: 오프라인에서 전체 기능 사용 가능, 앱 재실행 시 상태 복원
- Exception: E-15-1 저장소 손상/마이그레이션 실패 → 안전 모드 진입, 백업 복구 시도 안내

## 5. 정책 및 규칙

### 5.1 반복 일정 (가정 — 원본 미명시, 범위 한정)

- **P-01**: 이번 릴리스는 **없음/매일/매주/매월/매년**의 단순 반복만 지원한다. 종료 조건은 "종료일" 또는 "N회".
- **P-02**: 반복 일정의 개별 회차를 수정/삭제하면 "이 일정만 / 이후 모두"를 선택한다.
- **P-03**: 반복 일정의 알림은 각 회차마다 독립적으로 예약된다(향후 일정 범위 내에서만 실제 예약, 나머지는 도래 시 재예약).

### 5.2 완료 상태

- **P-04**: 완료 여부는 일정당 1개의 불리언 + 완료 시각(nullable)으로 관리한다.
- **P-05**: 완료된 일정도 수정 가능하며, 시간 변경 시 완료 상태는 유지된다.
- **P-06**: 미래 일정도 완료 체크할 수 있다(사용자 판단 존중).
- **P-07**: 대시보드 "완료율"은 (완료 수 / 전체 수) × 100, 전체 0건이면 0%로 표시.

### 5.3 캘린더 연동 / 중복

- **P-08**: 앱↔기본 캘린더 일정의 동일성 판정 = (외부 캘린더 이벤트 ID 매핑 존재) 우선, 없으면 (제목 + 시작시각 동일) 휴리스틱. 병합 시 사용자 편집(로컬) 필드를 보존.
- **P-08-1**: 캘린더에서 삭제된 외부 일정은 앱에서 "외부 삭제됨"으로 표시 후 다음 동기화에서 제거(가정).
- **P-08-2**: 충돌 해결 기본값은 "기기 캘린더 우선", 설정에서 "앱 우선"으로 변경 가능(가정).

### 5.4 알림

- **P-09**: 앱은 기기 재부팅·강제 종료 이후에도 미래 알림 예약을 복원한다(부팅 완료 시점 재예약).
- **P-10**: 한 일정의 사전 알림 오프셋은 최대 5개로 제한한다(가정).
- **P-10-1**: 알림 본문에 일정 제목 노출 여부는 사용자 설정으로 토글한다(민감정보 보호, 기본: 노출).

### 5.5 검색

- **P-11**: 검색 최소 글자 수는 1자. 2자 미만 검색은 결과 상한(예: 50건)과 함께 안내(가정).
- **P-12**: 검색 대상 필드 = 제목, 메모, 유형명. 완료/우선순위/기간은 필터로만.

### 5.6 계정 / 데이터

- **P-13**: 로그인 없이 모든 로컬 기능을 사용할 수 있어야 한다(계정은 선택).
- **P-14**: 계정 연동 해제 시 로컬 데이터는 삭제하지 않는다.
- **P-15**: 일정 제목/메모는 민감정보로 간주하고 로컬 저장 시 보호 수준을 설계 단계에서 정의한다(암호화 여부는 NFR/보안 설계에서 결정).

### 5.7 시간/시간대

- **P-16**: 일정 시각은 단말 로컬 시간대를 기준으로 저장·표시한다. 시간대 변경 시 표시 규칙은 설계에서 정의(가정: 저장은 UTC + TZ, 표시는 로컬).
- **P-17**: 날짜 경계(자정)는 단말 로컬 자정을 기준으로 한다.

## 7. 사용자 흐름 (User Flow)

### 7.1 최초 실행

1. 앱 실행 → 온보딩(간단 소개)
2. 알림 권한 요청(건너뛰기 가능)
3. (선택) 캘린더 접근 권한 요청
4. (선택) 계정 로그인
5. 대시보드(빈 상태) 진입 → "일정 추가" 유도

### 7.2 일정 등록 → 알림 → 완료 (핵심 흐름)

1. 대시보드/캘린더에서 "+" → 일정 작성 화면
2. 제목·일시·유형·우선순위·메모 입력
3. 사전 알림 오프셋 선택(예: 10분 전, 1일 전) + 정시 알림 on
4. 저장 → 검증 통과 → SQLite 저장 → 알림 예약
5. 오프셋 시각/정시에 로컬 알림 수신(모바일·워치)
6. 알림 또는 목록에서 일정 진입 → 체크박스 완료 토글
7. 대시보드 집계 갱신(완료율 상승)

### 7.3 검색

1. 검색 탭 → 검색어 입력
2. (선택) 유형/완료/기간 필터
3. 결과 목록 → 항목 선택 → 상세/수정

### 7.4 캘린더 연동

1. 설정 → 캘린더 연동 → 권한 동의
2. 가져올 캘린더 선택, 동기화 방향 설정
3. 외부 일정이 앱 뷰에 병합 표시(P-08)
4. 충돌/중복은 규칙에 따라 병합 또는 사용자 선택

### 7.5 계정 연동 (D-01 결정 전 기본 흐름)

1. 설정 → 계정 → 로그인(OAuth)
2. 동의 → 연동 완료 표시
3. (D-01=(a)면) 기기 간 동기화 시작 / (D-01=(c)면) 캘린더 연동 활성화만

### 7.6 상태 전이 (일정)

```
[작성중] --저장--> [예정]
[예정] --완료토글--> [완료]
[완료] --완료토글--> [예정]
[예정/완료] --수정--> (같은 상태 유지, 알림 재예약)
[예정/완료] --삭제--> [삭제됨] (알림 예약 제거)
[예정] --시작시각 경과 & 미완료--> [지남(미완료)]  (표시상 구분, 완료 토글 계속 가능)
```

## 9. Acceptance Criteria (검증 가능 형태)

표기: Given / When / Then

### AC-01 일정 등록

- Given 제목·시작일시·유형·우선순위를 입력했고
- When 저장을 누르면
- Then 일정이 목록·대시보드·캘린더 뷰에 나타나고, 앱 재실행 후에도 유지된다.

### AC-02 필수값 검증

- Given 제목이 비었거나 시작일시가 없을 때
- When 저장을 누르면
- Then 저장되지 않고 어떤 필드가 문제인지 안내가 표시된다.

### AC-03 종료<시작 검증

- Given 종료일시가 시작일시보다 이르면
- When 저장을 누르면
- Then 저장이 거부된다.

### AC-04 완료 토글과 집계

- Given 금일 일정 4건 중 1건이 완료 상태일 때
- When 미완료 1건을 완료로 토글하면
- Then 대시보드 완료 수가 2, 완료율이 50%로 갱신된다.

### AC-05 사전 알림 발송

- Given 30분 뒤 시작 일정에 "10분 전" 사전 알림을 설정했을 때
- When 시작 20분 전 시각이 되면
- Then 해당 일정의 로컬 알림이 1회 발송된다(제목/시각 포함, P-10-1 설정에 따라 제목 마스킹).

### AC-06 정시 알림 발송

- Given 정시 알림이 켜진 일정이 있을 때
- When 시작 시각이 되면
- Then "지금 시작" 알림이 1회 발송된다.

### AC-07 알림 권한 거부

- Given 사용자가 알림 권한을 거부한 상태에서
- When 사전/정시 알림이 있는 일정을 저장하면
- Then 일정은 저장되고, 알림이 동작하지 않음을 알리는 안내와 설정 이동 경로가 제공된다.

### AC-08 재부팅 후 알림 복원

- Given 미래 알림이 예약된 일정이 있고 기기를 재부팅했을 때
- When 부팅이 완료되면
- Then 해당 알림 예약이 복원되어 예정 시각에 발송된다.

### AC-09 수정 시 알림 재예약

- Given 알림이 예약된 일정의 시작 시각을 변경하고 저장하면
- When 저장이 완료되면
- Then 이전 예약은 취소되고 새 시각 기준으로 알림이 재예약된다.

### AC-10 삭제 시 알림 제거

- Given 알림이 예약된 일정을 삭제하면
- Then 일정과 그 일정의 모든 알림 예약이 제거된다.

### AC-11 유형별 필터

- Given "업무" 유형 일정 3건, "취미" 2건이 있을 때
- When 목록에서 "업무" 필터를 적용하면
- Then 업무 3건만 표시된다.

### AC-12 우선순위 정렬

- Given 우선순위가 섞인 일정 목록에서
- When "우선순위순" 정렬을 선택하면
- Then 높음 → 보통 → 낮음 순으로 정렬된다.

### AC-13 검색

- Given 제목에 "회의"가 포함된 일정 2건, 메모에 "회의"가 포함된 1건이 있을 때
- When "회의"로 검색하면
- Then 3건이 결과에 표시된다.

### AC-14 검색 + 필터

- Given AC-13 상태에서
- When "회의" 검색에 "완료=미완료" 필터를 더하면
- Then 미완료인 회의 일정만 표시된다.

### AC-15 대시보드 빈 상태

- Given 금일 일정이 0건이면
- When 대시보드를 열면
- Then "오늘 일정이 없습니다" 안내와 일정 추가 진입점이 표시되고 완료율은 0%다.

### AC-16 자정 경과

- Given 대시보드를 열어 둔 상태에서 자정이 지나면
- When 화면을 갱신하면
- Then 기준 날짜가 다음 날로 바뀌고 그 날짜의 집계가 표시된다.

### AC-17 테마 지정 유지

- Given 다크 테마와 강조색을 선택하면
- When 앱을 재실행하면
- Then 선택한 테마·강조색이 그대로 적용되어 있다.

### AC-18 캘린더 읽기 연동

- Given 캘린더 접근 권한을 허용하고 캘린더 1개를 선택하면
- When 앱의 캘린더 뷰를 열면
- Then 해당 캘린더의 일정이 앱 일정과 함께 병합 표시된다.

### AC-19 캘린더 중복 병합

- Given 앱 일정과 외부 캘린더 일정이 P-08 기준으로 동일하다고 판정되면
- When 캘린더 뷰를 보면
- Then 중복 없이 1건으로 표시되고 사용자가 편집한 로컬 필드가 보존된다.

### AC-20 계정 없이 사용

- Given 로그인하지 않은 상태에서
- When F-01~F-11, F-13, F-15 기능을 사용하면
- Then 모두 정상 동작한다(계정 요구로 막히지 않는다).

### AC-21 계정 연동/해제

- Given 계정을 연동한 뒤 설정에서 연동을 해제하면
- Then 연동 상태 표시가 사라지고 로컬 일정 데이터는 그대로 유지된다.

### AC-22 오프라인 동작

- Given 네트워크가 없는 상태에서
- When 일정 등록·수정·삭제·완료·검색을 하면
- Then 모두 정상 동작하고, 네트워크 복구 시 (D-01=(a)인 경우) 동기화가 재개된다.

### AC-23 워치 완료 체크 반영

- Given 모바일과 페어링된 워치에서 금일 일정을 완료로 토글하면
- When 모바일 대시보드를 보면
- Then 완료 상태와 집계가 동일하게 반영된다.

### AC-24 데이터 마이그레이션

- Given 이전 스키마로 저장된 데이터가 있는 상태에서 앱을 업데이트하면
- When 앱을 실행하면
- Then 마이그레이션이 수행되어 기존 일정이 유실 없이 표시된다.
