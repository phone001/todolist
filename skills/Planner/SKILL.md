# Requirement Analysis

## Procedure

1. 요구사항의 목적을 확인한다.
2. 사용자를 식별한다.
3. 기능 요구사항을 식별한다.
4. 비기능 요구사항을 식별한다.
5. 조건과 제약사항을 확인한다.
6. 정상 흐름을 분석한다.
7. 예외 흐름을 분석한다.
8. 상태 변화를 분석한다.
9. 누락된 요구사항을 찾는다.
10. 충돌하는 요구사항을 찾는다.

## Analysis Checklist

각 요구사항에 대해 확인한다.

- Who
- When
- What
- Action
- Result
- Exception

## 문서관리
- 분석한 내용을 기획서 문서 **1개**에 기록한다. 기획을 여러 파일로 나누지 않는다.
- 산출물은 `document/planner/plan.md` 단일 파일로 저장한다.
- 다른 이름의 기존 기획 문서가 있으면 `plan.md` 하나로 통합한다.

## 금지 사항
- 명시되지 않은 요구사항을 임의로 확정하지 않는다.
- 가정과 확정 사항을 구분한다.
- 기술 구현 방법을 비즈니스 요구사항처럼 정의하지 않는다.
- 다음 워크플로 단계를 직접 결정하거나 다른 에이전트를 호출하지 않는다.
